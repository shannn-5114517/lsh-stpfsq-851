## 一、一句话说清 sCPU 是什么

**sCPU = 一台能"自动执行程序"的机器。**

**它只认 3 条指令**（每条 8 位）：

| 指令 | 汇编写法 | 作用 | 机器码格式 |
| --- | --- | --- | --- |
| **`add`** | `add r1, r2, r3` | 两个寄存器相加 | `00` + `rd` + `rs1` + `rs2` |
| **`li`** | `li r0, 10` | 把一个数装进寄存器 | `10` + `rd` + `imm`(4位) |
| **`bner0`** | `bner0 r1, 4` | 不相等就跳转 | `11` + `addr`(4位) + `rs2` |

**程序 = 一串指令**（放在 ROM 里）；
**CPU 的工作 = 不停地「取下一条 → 执行 → 再取下一条」**。

> **这就是"存储程序"思想** —— 程序是数据，和数据放在一起，由 CPU 自动读取执行。

## 二、整体架构：六个部件

```
                    ┌──────────────────────────────────────────────┐
                    │                                              │
                    ↓                                              │
              ┌──────────┐                                        │
              │    PC    │  ← 程序计数器（存"下一条指令的地址"）    │
              └────┬─────┘                                        │
                   │ 地址                                          │
                   ↓                                               │
              ┌──────────┐                                        │
              │   ROM    │  ← 指令存储器（按地址取指令）            │
              └────┬─────┘                                        │
                   │ 8 位指令                                       │
                   ↓                                               │
              ┌──────────┐                                        │
              │   dec    │  ← 指令译码器（把指令拆成"控制信号"）    │
              └────┬─────┘                                        │
                   │ opcode/rd/rs1/rs2/imm/addr                    │
                   ↓                                               │
    ┌──────────────┴───────────────┐                              │
    ↓                              ↓                              │
┌────────┐                    ┌──────────┐                        │
│  GPR   │  ← 4 个 8 位寄存器  │   ALU    │  ← 8 位加法器          │
│ (双读口)│                    │ (加法器) │                        │
└───┬────┘                    └────┬─────┘                        │
    │ rdata1/rdata2                │ 结果                          │
    │                              ↓                               │
    │                        ┌──────────┐                          │
    └───────────────────────→│  Cmp     │  ← 比较器（bner0 用）    │
                             └────┬─────┘                          │
                                  │ 相等/不等                     │
                                  ↓                               │
                             ┌──────────┐                          │
                             │ MUX(PC)  │  ← 选 PC+1 还是 addr     │
                             └────┬─────┘                          │
                                  │                                │
                                  └────────────────────────────────┘
                                        （反馈回 PC）
```

**六个部件，一句话记住**：

| 部件 | 作用 | 类比 |
| --- | --- | --- |
| **PC** | 记"现在执行到第几条" | **书签** |
| **ROM** | 存程序 | **菜谱本** |
| **dec** | 把指令翻译成控制信号 | **翻译官** |
| **GPR** | 存数据的 4 个格子 | **4 个碗** |
| **ALU** | 做加法 | **计算器** |
| **Cmp** | 比较两个数 | **裁判** |

## 三、模块详解

### 模块 1：`PC`（程序计数器）

#### 它是什么

**一个 8 位寄存器** —— 里面存着"当前执行到第几条指令"（指令的地址）。

#### 接口

| 端口 | 方向 | 位宽 | 说明 |
| --- | :-: | :-: | --- |
| `pc_next` | 输入 | 8 | **下一个 PC 值**（来自顶层 MUX）|
| `WE` | 输入 | 1 | 写使能（接常量 1）|
| `clock` | 输入 | 1 | 时钟 |
| `pc_out` | 输出 | 8 | 当前 PC 值 |

#### 内部

```
        ┌──────────────┐
pc_next │              │
（8位）─→│  Register    │──→ pc_out（8位）
  clk  ─→│  (8位)       │
        └──────────────┘
```

**—— 就 1 个 8 位寄存器**。

#### 为什么这么设计

**PC 的更新逻辑（PC+1 / 跳转）放在顶层，不放模块里** —— 因为：

- **阶段 1/2**：`PC ← PC+1`
- **阶段 3**：`PC ← MUX(PC+1, addr)`

**如果 MUX 做在 PC 模块内部** → **阶段 2 升阶段 3 时要改模块**；
**放在顶层** → **PC 模块一行都不用改** ✅

#### 答辩可能问

> **Q：PC 为什么是 8 位？**
>
> A：**8 位地址 → 能寻址 256 条指令**（2⁸ = 256）。
> ysyx F6 讲义原话：「PC 寄存器的位宽只有 8 位，因此程序最多只能包含 256 条指令」。

### 模块 2：`ROM`（指令存储器）

#### 它是什么

**一个 256 × 8 的只读存储器** —— 存着整个程序（最多 256 条指令）。

#### 接口

| 端口 | 方向 | 位宽 | 说明 |
| --- | :-: | :-: | --- |
| `A`（Address）| 输入 | 8 | **地址**（来自 PC）|
| `D`（Data Out）| 输出 | 8 | **该地址的指令** |

**⚠️ ROM 是只读的** —— **没有时钟、没有写使能**。

#### 内部原理（讲义怎么说）

> 「给定地址 `addr`，可以读出 ROM 中的相应存储字：
> **地址译码器**将输入的地址转换成一组**独热码**，只有 `addr` 对应的**字线**有效，
> 使得该行中存放的信息可以通过**与门**，其余行被过滤为 `0`。
> 被选中的存储字的每一位经过**或门**传输到**位线**，向存储器外部输出。」

**—— 所以 ROM 本质上是「一个数据端为常数的多路选择器（MUX）」** ✅

#### 我们用 Logisim 自带的 ROM

**属性**：

| 属性 | 值 |
| --- | --- |
| `Address Bit Width` | **8** |
| `Data Bit Width` | **8** |

**内容（程序）**：

| 地址 | Hex | 汇编 |
| --- | :-: | --- |
| `00` | `8a` | `li r0, 10` |
| `01` | `90` | `li r1, 0` |
| `02` | `a0` | `li r2, 0` |
| `03` | `b1` | `li r3, 1` |
| `04` | `17` | `add r1, r1, r3` |
| `05` | `29` | `add r2, r2, r1` |
| `06` | `d1` | `bner0 r1, 4` |
| `07` | `df` | `bner0 r3, 7` |

#### 为什么用 ROM 而不是 RAM

**sISA 的 3 条指令都不访问存储器**（只有"取指"要读）——
**→ 不需要写功能 → 用 ROM 更简单** ✅

### 模块 3：`dec`（指令译码器）⭐

#### 它是什么

**把 8 位"指令"翻译成"控制信号"** —— **整个 CPU 的"大脑"**。

#### 接口

| 端口 | 方向 | 位宽 | 说明 |
| --- | :-: | :-: | --- |
| `instr` | **输入** | 8 | 指令 |
| `is_add` | 输出 | 1 | 是不是 add |
| `is_li` | 输出 | 1 | 是不是 li |
| `is_bner0` | 输出 | 1 | 是不是 bner0 |
| `rd` | 输出 | 2 | 目的寄存器号 |
| `rs1` | 输出 | 2 | 源寄存器 1 |
| `rs2` | 输出 | 2 | 源寄存器 2 |
| `imm` | 输出 | 4 | 立即数 |
| `addr` | 输出 | 4 | 跳转地址 |

**⚠️ 注意**：**只有 `instr` 是输入，其余 8 个全是输出**。

#### 内部结构

```
instr（8 位）
  ├──→ [Splitter #1] 8 → opcode(2) + rd(2) + rs1(2) + rs2(2)
  │                        ↓
  │                   [2-4 译码器] → Y0/Y1/Y2/Y3
  │                        ↓
  │                   is_add / is_li / is_bner0
  │
  ├──→ [Splitter #2] 8 → imm(bit 3~0) + 高4位（不用）
  │                        ↓
  │                       imm
  │
  └──→ [Splitter #3] 8 → addr(bit 5~2) + 其他（不用）
                           ↓
                          addr
```

#### ⭐ 三个 Splitter 的设置（**最容易错的地方**）

**Splitter #1**（拆四个字段）：

| 属性 | 值 |
| --- | --- |
| `Input Bit Width` | 8 |
| `Fan Out` | **4** |
| `Bit 0~1` | **0** → `rs2` |
| `Bit 2~3` | **1** → `rs1` |
| `Bit 4~5` | **2** → `rd` |
| `Bit 6~7` | **3** → `opcode` |

**Splitter #2**（拆 imm）：

| `Bit 0~3` | **0** → `imm`（4 位）|
| `Bit 4~7` | 1（不用）|

**Splitter #3**（拆 addr）：

| `Bit 0~1` | 0（不用）|
| **`Bit 2~5`** | **1** → **`addr`** ⭐ |
| `Bit 6~7` | 2（不用）|

**⚠️ 为什么 `addr` 要单独拆**：

```
bit 7~6 ：opcode
bit 5~4 ：rd          ┐
bit 3~2 ：rs1         ├─ addr = bit 5~2（跨越了 rd 和 rs1！）
bit 1~0 ：rs2         ┘
```

**`addr` 跨越了两个字段** → **必须单独一个 Splitter** ✅

#### 讲义怎么说

> 「要识别输入的取值，最适合的电路就是**译码器**！
> 由于 `opcode` 只有 2 位，我们可以使用一个 **2-4 译码器**，
> 它输出的**独热码**可以指示当前指令属于何种指令，
> 这样的译码器称为**指令译码器**。
> 这组独热码通常作为**控制信号**，用于控制部分电路如何工作。」

**我们的映射**：

| opcode | Y 输出 | 指令 |
| :-: | :-: | --- |
| `00` | **Y0** → `is_add` | add |
| `01` | Y1（不用）| sISA 无此指令 |
| `10` | **Y2** → `is_li` | li |
| `11` | **Y3** → `is_bner0` | bner0 |

#### 答辩可能问

> **Q：为什么用"译码器"而不是"比较器"来识别指令？**
>
> A：**译码器输出的是"独热码"** —— 天然就是"哪一条指令"的信号，
> **可以直接当控制信号用**；而且**指令变多时，译码器只需要加宽**（比如 3 位 opcode 用 3-8 译码器），
> 比一堆比较器更规整。

### 模块 4：`gpr`（通用寄存器组）⭐⭐

#### 它是什么

**4 个 8 位寄存器 + 2 个读口 + 1 个写口**。

**—— 这就是讲义说的「双端口 RAM」**。

#### 接口

| 端口 | 方向 | 位宽 | 说明 |
| --- | :-: | :-: | --- |
| `raddr1` | 输入 | 2 | **读地址 1** |
| `rdata1` | **输出** | 8 | 读数据 1 |
| `raddr2` | 输入 | 2 | **读地址 2** |
| `rdata2` | **输出** | 8 | 读数据 2 |
| `waddr` | 输入 | 2 | 写地址 |
| `wdata` | 输入 | 8 | 写数据 |
| `wen` | 输入 | 1 | **写使能** |
| `clk` | 输入 | 1 | 时钟 |

#### 内部结构

```
        ┌────────────────┐
raddr1 →│  MUX1（4 选 1）│─→ rdata1
        └────────┬───────┘
                 ↑
      ┌──────┬───┴───┬──────┐
      ↓      ↓       ↓      ↓
    [A0]   [A1]   [A2]   [A3]
      ↑      ↑       ↑      ↑
      └──────┴───┬───┴──────┘
                 ↑
              wdata（8 位，广播给 4 个）
                 
              waddr → 2-4 译码器 → Y0~Y3
                     Y_i · wen → 与门 → Reg_i 的 WE
                 
raddr2 →│  MUX2（4 选 1）│─→ rdata2
```

#### ⭐ 核心机制：为什么"只有被选中的寄存器被写"

**关键在 `wen` 和译码器的配合**：

```
waddr = 2（二进制 10）
  ↓
2-4 译码器 → Y0=0, Y1=0, Y2=1, Y3=0
  ↓
Y2 · wen（=1）→ AND2 输出 1
  ↓
只有 Reg2 的 WE = 1
  ↓
时钟沿：只有 Reg2 写入 wdata ✅
其他 3 个 WE = 0 → 保持不变 ✅
```

**—— 这就是"写使能译码"** ✅

**注意**：**`wdata` 是"广播"给 4 个寄存器的 D 的** ——
**每个寄存器都"看到"了数据，但只有 WE=1 的那个会真的存下来**。

#### 讲义怎么说

> 「GPR 的电路本质也是一个**存储器**。不过 GPR 需要作为目的寄存器被指令写入，
> 因此 GPR 是一个支持写入的存储器，即 **RAM**。
>
> 对于 RAM 来说，并非所有时刻都需要进行写入操作，例如，在执行 `bner0` 指令时，
> 就不需要写入 GPR，因此还需要一个**写使能信号 `EN`**，指示当前是否需要写入。」

#### 为什么需要"双读口"

**`add` 指令要同时读两个寄存器**：

```
add r1, r1, r3
     ↑   ↑  ↑
     rd  rs1 rs2
```

**→ 要同时读 `R[rs1]` 和 `R[rs2]` → 必须有两个读口** ✅

（如果只有一个读口，就要读两次，一条指令要占两个时钟周期。）

#### 答辩可能问

> **Q：`add r1, r1, r1` 这种"读和写是同一个寄存器"的情况，会出错吗？**
>
> A：**不会**。因为：
> - **读是组合逻辑**（`rdata1 = gpr[rs1]`，立即出结果）
> - **写在时钟沿发生**（`gpr[rd] <= wdata`）
> - **读发生在"写之前"** → 读到的是旧值 ✅
>
> 这正是**非阻塞赋值**保证的语义："所有寄存器在同一时刻更新，读到的都是旧值"。

### 模块 5：`ALU`（算术逻辑单元）

#### 它是什么

**一个 8 位加法器** —— 目前只做加法。

#### 接口

| 端口 | 方向 | 位宽 | 说明 |
| --- | :-: | :-: | --- |
| `RegA` | 输入 | 8 | 操作数 1（= R[rs1]）|
| `RegB` | 输入 | 8 | 操作数 2（= R[rs2]）|
| `result` | **输出** | 8 | **加法结果** |
| `Carry` | 输出 | 1 | 进位 |
| `Dout` | 输出 | 8 | 三态输出（备用，**本设计未使用**）|
| `OE` | 输入 | 1 | 输出使能（配合 Dout）|

#### 内部

```
        ┌──────────┐
RegA ──→│          │
        │  Adder   │──→ result（8 位）
RegB ──→│  (8位)   │──→ Carry
        └──────────┘
             ↓
        [三态缓冲器] ──→ Dout（受 OE 控制）
```

#### ⚠️ 一个"坑"：`result` 和 `Dout` 是两个输出

**`result`** 是加法器直连的输出；
**`Dout`** 是经过三态缓冲器的输出（受 `OE` 控制）。

**如果两者在顶层都接到同一处** → **两个输出驱动同一根线** → **冲突（红线）** ❌

**→ 本设计只用 `result`**，`Dout` 和 `OE` 悬空。

#### 讲义怎么说

> 「读出源操作数后，`add` 指令的行为是**将两数相加**，然后将加法结果写入 `rd` 寄存器。
> 前者可以通过**加法器**实现。」

### 模块 6：`Cmp`（比较器）

#### 它是什么

**比较两个 8 位数** —— 给 `bner0` 用。

#### 接口

| 端口 | 方向 | 说明 |
| --- | :-: | --- |
| `A` | 输入 8 位 | 比较数 1（**bner0 时 = R[0]**）|
| `B` | 输入 8 位 | 比较数 2（= R[rs2]）|
| `>` | 输出 | A > B |
| **`=`** | 输出 | **A = B** |
| `<` | 输出 | A < B |

#### ⭐ 为什么 `A` 接 `rdata1` 就够

**因为 `bner0` 时 `MUX_raddr1` 把 `raddr1` 切换成 0**：

```
bner0 指令：is_bner0 = 1
  ↓
MUX_raddr1 的 S = 1 → 选 D1 = 0
  ↓
gpr.raddr1 = 0 → rdata1 = R[0] ✅
  ↓
cmp.A = R[0]，cmp.B = R[rs2]
  ↓
比较的正是 "R[0] 和 R[rs2]" —— bner0 的语义 ✅
```

**—— 这是讲义的精髓，也是整个设计最巧妙的地方** ⭐

#### 注意：Comparator 没有 `≠` 输出

**我们要的是"不相等"**，所以：

```
bne = NOT(cmp.=)
```

**用一个非门实现** ✅

### 模块 7：顶层（`main`）—— 把六个模块连起来

#### 四个关键 MUX

| MUX | 选择端 | D0 | D1 | 输出 |
| --- | --- | --- | --- | --- |
| **`MUX_raddr1`** | **`is_bner0`** | `rs1` | **常量 0** | `gpr.raddr1` |
| **`MUX_wdata`** | **`is_add`** | `imm8` | **`alu.result`** | `gpr.wdata` |
| **`MUX_pc`** | **`pc_taken`** | `PC+1` | **`addr8`** | `pc.pc_next` |

#### 几个"胶水"元件

| 元件 | 作用 |
| --- | --- |
| **Bit Extender**（×2）| **`imm`（4 位）→ 8 位**、**`addr`（4 位）→ 8 位**（零扩展）|
| **OR 门** | `wen = is_add OR is_li` |
| **AND 门** | `pc_taken = is_bner0 AND bne` |
| **NOT 门** | `bne = NOT(cmp.=)` |

## 四、三条指令怎么走

### `li r0, 10`（机器码 `8a`）

**逐拍过程**：

| 步骤 | 发生了什么 | 信号 |
| --- | --- | --- |
| **① 取指** | PC=0 → ROM[0] = `8a` | `instr = 8a` |
| **② 译码** | 拆出 opcode=`10`, rd=`00`, imm=`1010` | `is_li = 1` |
| **③ 控制信号** | `wen = is_add OR is_li = 1` | — |
| **④ 写回数据** | `MUX_wdata` 的 S=`is_add`=0 → 选 D0 = `imm8` = 10 | `wdata = 10` |
| **⑤ 写地址** | `MUX_raddr1` 的 S=`is_bner0`=0 → 选 `rs1`（无关）| — |
| **⑥ 写寄存器** | `waddr = rd = 0`，时钟沿 → **Reg0 = 10** | — |
| **⑦ 更新 PC** | `MUX_pc` 的 S=`pc_taken`=0 → 选 `PC+1` = 1 | `PC = 1` |

**—— 一拍完成** ✅

---

### `add r1, r1, r3`（机器码 `17`）

| 步骤 | 发生了什么 | 信号 |
| --- | --- | --- |
| **① 取指** | PC=4 → ROM[4] = `17` | `instr = 17` |
| **② 译码** | opcode=`00`, rd=`01`, rs1=`01`, rs2=`11` | `is_add = 1` |
| **③ 读操作数** | `raddr1 = rs1 = 1` → `rdata1 = R[1]`；`raddr2 = rs2 = 3` → `rdata2 = R[3]` | `rdata1 = 0`，`rdata2 = 1` |
| **④ ALU** | `result = 0 + 1 = 1` | — |
| **⑤ 写回数据** | `MUX_wdata` 的 S=`is_add`=1 → 选 D1 = `result` = 1 | `wdata = 1` |
| **⑥ 写寄存器** | `waddr = rd = 1`，`wen = 1` → 时钟沿 → **Reg1 = 1** | — |
| **⑦ 更新 PC** | `pc_taken = 0` → `PC = 5` | — |

**—— 一拍完成** ✅

**⚠️ 关键**：**`MUX_wdata` 选的是"加法结果"** —— **这就是"写回数据选择"的意义**。

---

### `bner0 r1, 4`（机器码 `d1`）

| 步骤 | 发生了什么 | 信号 |
| --- | --- | --- |
| **① 取指** | PC=6 → ROM[6] = `d1` | `instr = d1` |
| **② 译码** | opcode=`11`, rs2=`01`, addr=`0100`=4 | `is_bner0 = 1` |
| **③ 读 R[0]** | **`MUX_raddr1` 的 S=`is_bner0`=1 → 选 D1=0** → `raddr1=0` → **`rdata1 = R[0] = 10`** | ⭐ |
| **④ 读 R[rs2]** | `raddr2 = rs2 = 1` → `rdata2 = R[1] = 1` | — |
| **⑤ 比较** | `cmp.A = 10`，`cmp.B = 1` → **不相等** → `cmp.= = 0` → **`bne = 1`** | — |
| **⑥ 跳转判断** | `pc_taken = is_bner0 · bne = 1 · 1 = 1` | — |
| **⑦ 更新 PC** | `MUX_pc` 的 S=1 → 选 D1 = `addr8` = **4** → **PC = 4**（跳回循环体）| ⭐ |
| **⑧ 不写 GPR** | `wen = is_add OR is_li = 0` → **GPR 不变** | ⭐ |

**—— 一拍完成，PC 从 6 跳到 4** ✅

**当 `r1 = 10 = r0` 时**：

```
cmp.== 1 → bne = 0 → pc_taken = 0 → PC = 6+1 = 7  ✅
```

**—— 循环结束，PC 到 7（停机）** ✅

## 五、控制信号总结（答辩杀手锏）

**这张表是整个设计的"灵魂"** —— 讲义原文：

| 指令 | `wdata` 的选择 | `wen` | `raddr1` 的选择 | 更新 PC 的选择 |
| :-: | --- | :-: | --- | --- |
| **`add`** | **加法器的输出** | **1** | **指令的 `rs1`** | **`PC + 1`** |
| **`li`** | **立即数** | **1** | `X`（无关）| **`PC + 1`** |
| **`bner0`** | `X`（无关）| **0** | **`0`** | **指令的 `addr`** |

**`X` = don't care（无关项）** —— **选什么都可以，不影响正确性**。

**—— 三个 MUX 正好实现这张表的三列（`wdata`、`raddr1`、PC）** ✅

**讲义里那句话**：

> 「**在 CPU 上执行程序 = 用程序编译出的指令序列控制 CPU 电路进行状态转移。**」

**我们的电路完全印证了这一点**：

```
指令 → 译码器 → 控制信号（is_add/is_li/is_bner0）
     → 控制三个 MUX 的选择端
     → 决定"数据往哪流"
     → 完成指令的功能
```

## 六、答辩常见问题

### Q1：你这个 CPU 能做什么？

> **能执行 sISA 的 3 条指令**（`add` / `li` / `bner0`），
> **可以运行带循环的程序** —— 比如 `1+2+…+10`（最终 `R[2]=55`）、`1+3+5+7+9`（`R[2]=25`）。

### Q2：为什么 PC 是 8 位、GPR 是 4 个 8 位？

> **PC 8 位** → 可寻址 256 条指令（2⁸）；
> **GPR 4 个** → 2 位地址刚好够选，且 sISA 只需要 4 个。

### Q3：`bner0` 为什么要读 `R[0]`？

> **因为 `bner0` 是「和 `R[0]` 比较」** —— `R[0]` 相当于"循环上界"寄存器。
> 讲义设计里，`R[0]` 被用作"哨兵值"，循环时判断当前值是否到达上界。

### Q4：为什么 `bner0` 时 `raddr1` 要选 `0`？

> **因为 `raddr1` 平时接 `rs1`（`add` 用），但 `bner0` 要读 `R[0]`** ——
> 所以用 `MUX_raddr1` 切换：**`is_bner0 ? 0 : rs1`**。

**⚠️ 这是整个设计最巧妙的地方** —— **不增加 GPR 的端口，只加一个 MUX** ✅

### Q5：为什么 `bner0` 不写 GPR？

> **因为 `wen = is_add OR is_li`** —— `bner0` 时两者都是 0 → `wen = 0` → **4 个与门全 0 → 所有寄存器 WE=0 → 不写**。

### Q6：如果两条指令同时满足会怎样？

> **不会发生** —— **opcode 是 2 位，只能取 4 个值之一**，
> 而 `is_add`（`00`）、`is_li`（`10`）、`is_bner0`（`11`）是**互斥**的。

### Q7：你的 CPU 和"计算器"有什么区别？

> **计算器只能算"一次"**，**CPU 能"循环"** ——
> **因为 `bner0` 能改 PC**，让程序"跳回去重跑一段"。
>
> **这就是"图灵完备"的基础** —— **有跳转，就能表达任意算法** ✅

### Q8：程序是怎么"装进"CPU 的？

> **程序存在 ROM 里**（256×8），**PC 指向第一条**。
> **—— 这就是"存储程序"思想**：**程序是数据，和数据放在一起**。

### Q9：为什么 `li` 的立即数只有 4 位？

> **因为指令只有 8 位**：`10`（2 位 opcode）+ `rd`（2 位）+ `imm`（4 位）= 8 位。
> **4 位立即数范围 0~15** —— 如果不够用，可以多来几条 `li` 拼（F6 会讲符号扩展）。

### Q10：你调试时遇到最大的困难是什么？

> **① 子电路方块"左边输入、右边输出"** —— Probe 接错边，看到的是"输入信号"不是"寄存器值"（`r1`/`r2` 显示 `u`）。
> **② `ALU` 有 `result` 和 `Dout` 两个输出** —— 都接到同一处会冲突（红线）。
> **③ `bne` 忘了加非门** —— 跳转条件反了。

## 七、我踩过的坑

### 坑 1：Probe 接到 `gpr` 的"输入侧"

**现象**：`r1`、`r2` 显示 `u`。

**原因**：**`gpr` 方块左边是输入（`wdata`/`wen`/`raddr`），右边是输出（`r0_out`~`r3_out`）**。
Probe 接在左边 → 读到的是"输入信号"。

**教训**：**子电路方块的"边"很重要** —— **输入在左、输出在右**。

### 坑 2：ROM 只填了 6 条

**现象**：程序跑不到 `bner0`。

**原因**：`Contents` 里只有 `8a 90 a0 b1 17 29`，缺 `d1`、`df`。

### 坑 3：`bne` 缺非门

**现象**：跳转条件反了（"相等才跳"）。

**原因**：`bne` 直接接 Comparator 的 `=` 输出 —— 那是"相等"。

**修正**：`cmp.=` → NOT → `bne`。

### 坑 4：`ALU` 的 `result` / `Dout` 冲突

**现象**：仿真出现红线。

**原因**：两个 8 位输出都接到了同一处。

**修正**：只用 `result`。
