# 简易处理器 sCPU 设计报告

> **项目名称**：基于 Logisim 的 sISA 指令集简易处理器
> **覆盖内容**：ysyx F5（支持数列求和的简单处理器）+ ysyx F6（指令集增强与输入输出）
> **实现工具**：Logisim-evolution 4.0.0
> **日期**：2026 年 10 月

---

## 摘要

本报告记录了一个**从零开始、完全用数字逻辑门和寄存器搭建的 8 位处理器**（sCPU）的完整设计过程。

处理器分两个阶段完成：

| 阶段 | 内容 | 核心成果 |
| --- | --- | --- |
| **F5** | 实现 sISA 的 3 条指令：`add` / `li` / `bner0` | 运行「1+2+…+10」得到 **PC=7、R[2]=55** |
| **F6** | 指令集增强 + 输入输出（sISA v3.0） | `li` 支持移位立即数、`bner0` 支持相对跳转、新增 `io` 指令驱动 **LED / 七段数码管 / 拨码开关 / 按钮** |

**最终，sCPU 从一个「只能跑完看寄存器」的计算电路，变成了一个「能读外设、写外设」的完整处理器。**

---

## 一、项目概述

### 1.1 背景

计算机的本质是「**存储程序**」：程序作为数据存在存储器里，CPU 按顺序取出、译码、执行，并更新程序计数器（PC）。

**讲义的核心论断**：

> 「**在 CPU 上执行程序 = 用程序编译出的指令序列控制 CPU 电路进行状态转移。**」

本项目的目的，就是**用数字逻辑电路把这个论断"造"出来**。

### 1.2 目标

| 目标 | 说明 |
| --- | --- |
| **硬件层** | 用 Logisim 搭建一个完整的处理器（PC / ROM / 译码器 / 寄存器组 / ALU / 比较器 / 外设） |
| **指令层** | 实现 sISA 的全部指令（F5 的 3 条 → F6 的 4 条） |
| **验证层** | 通过「1+2+…+10」等程序验证正确性 |
| **交互层** | （F6）让处理器能跟外部设备交互 |

### 1.3 验收标准

**F5 的验收标准**（讲义原文）：

> 「运行结束后，**PC = 7，GPR = 55**」

**我的验证结果**：

```
程序：1+2+…+10
最终：PC = 7，R[0]=10，R[1]=10，R[2]=55，R[3]=1   ✅
```

## 二、指令集设计

### 2.1 sISA v1（F5 的三条指令）

**指令位宽 8 位，PC 8 位，GPR 4 个 × 8 位**：

```
 7  6 5  4 3   2 1   0
+----+----+-----+-----+
| 00 | rd | rs1 | rs2 |   add:   R[rd] = R[rs1] + R[rs2]
+----+----+-----+-----+
| 10 | rd |    imm    |   li:    R[rd] = imm（高位补 0）
+----+----------+-----+
| 11 |   addr   | rs2 |   bner0: if (R[0] != R[rs2]) PC = addr
+----+----------+-----+
```

### 2.2 sISA v2.0（F6 前半：指令增强）

**F5 的三个局限**：

| 局限 | 后果 |
| --- | --- |
| **`li` 只能装 0~15** | 装 192 要 **1 条 li + 6 条 add** |
| **`bner0` 只能跳 0~15**（绝对地址）| 程序一大就跳不到 |
| （隐藏）**操作码 `01` 空着** | 有扩展空间 |

**F6 的增强**：

```
| 10 | rd |  s  | imm |   li:    R[rd] = imm << (s << 1)
+----+----+-+---+-----+
| 11 |  offset  | rs2 |   bner0: if (R[0] != R[rs2]) PC = PC + sign_ext(offset)
```

**`li` 的 `s` 字段**：**`imm`（2 位）放在 8 位的哪一段**

| `s` | 布局 | `imm=11` 时 |
| :-: | :-: | :-: |
| `00` | `00 00 00 imm` | 3 |
| `01` | `00 00 imm 00` | 12 |
| `10` | `00 imm 00 00` | 48 |
| `11` | `imm 00 00 00` | 192 |

**`bner0` 的 `offset`**：**相对 PC 的偏移**（4 位补码，**-8 ~ +7**）

### 2.3 sISA v3.0（F6 完整：加输入输出）

```
 7  6 5  4 3   2 1   0
+----+----+---+-------+
| 00 | rd | rs1 | rs2 |   add
+----+----+---+-------+
| 01 | rd |i/o|  idx  |   io:   R[rd] <=> dev[idx]      ← 新增
+----+----+---+-------+
| 10 | rd | s |  imm  |   li
+----+----+---+-------+
| 11 |  offset  | rs2 |   bner0
+----+----------+-----+
```

**`io` 指令的语义**：

| `i/o` | 操作 | 数据流向 |
| :-: | --- | --- |
| **0** | **输入** | **`dev[idx]` → `R[rd]`** |
| **1** | **输出** | **`R[rd]` → `dev[idx]`** |

### 2.4 ⭐ 指令集演进的思考（亮点铺垫）

**三条演进线索**：

| 线索 | 表现 |
| --- | --- |
| **① 位数腾挪** | `li` 从「4 位 imm」变成「2 位 s + 2 位 imm」 —— **牺牲"立即数位数"，换取"4 种移位量"** |
| **② 语义转变** | `bner0` 从「绝对地址」变成「相对偏移」 —— **同一字段，语义变了，但位数不变** |
| **③ 槽位利用** | 操作码 `01` 在 F5 里空着，F6 正好用它加 `io` |

**—— 这三条都是「ISA 设计的核心技巧」**（详见第七章亮点 4）

## 三、电路架构

### 3.1 总体结构

```
                        ┌─────────────────────────────────────────┐
                        │                                         │
                        ↓                                         │
                   ┌─────────┐                                   │
                   │   PC    │  ← 程序计数器（8 位寄存器）        │
                   └────┬────┘                                   │
                        │ 地址                                     │
                        ↓                                         │
                   ┌─────────┐                                   │
                   │   ROM   │  ← 指令存储器（256 × 8）           │
                   └────┬────┘                                   │
                        │ 8 位指令                                 │
                        ↓                                         │
                   ┌─────────┐                                   │
                   │   dec   │  ← 指令译码器（译码 + 控制信号）    │
                   └────┬────┘                                   │
                        │                                          │
        ┌───────────────┼───────────────┬──────────────┐          │
        ↓               ↓               ↓              ↓          │
  ┌───────────┐  ┌───────────┐   ┌───────────┐  ┌───────────┐     │
  │MUX_raddr1 │  │MUX_wdata  │   │ MUX_addB  │  │ 输入 MUX  │     │
  └─────┬─────┘  └─────┬─────┘   └─────┬─────┘  └─────┬─────┘     │
        ↓              ↑               ↓              ↑           │
  ┌───────────┐        │         ┌───────────┐  ┌───────────┐     │
  │    gpr    │────────┘         │ Adder_pc  │  │ 拨码/按钮 │     │
  │（双读口） │                  └─────┬─────┘  └───────────┘     │
  └─────┬─────┘                        │                          │
        │                              └──────────────────────────┘
        ├──→ ALU（加法器）──→ MUX_wdata.D1
        ├──→ Cmp（比较器）──→ pc_taken ──→ MUX_addB.S
        ├──→ led_reg ──→ LED0~7
        └──→ seg7_reg ──→ seg7_rom ──→ 七段数码管
```

### 3.2 数据通路的「三段」

| 段 | 内容 |
| --- | --- |
| **取指段** | `PC → ROM → instr` |
| **执行段** | `instr → dec → 控制信号 → MUX 选择 → GPR / ALU / Cmp` |
| **写回段** | `MUX_wdata → gpr.wdata`（`wen=1` 时写） |

**—— 讲义原话**：

> 「如果把取出的指令作为边界，将 sCPU 划分为左右两侧：**左侧向右侧传递的信息只有指令**。**右侧电路唯一的输入就是指令，它完全受到指令的控制。**」

### 3.3 控制信号总表（**全设计的灵魂**）

| 指令 | `wdata` 选什么 | `wen` | `raddr1` 选什么 | 加法器 B 端 |
| :-: | --- | :-: | --- | --- |
| **`add`** | `alu.result` | **1** | `rs1` | **常量 1** |
| **`li`** | `imm8` | **1** | X（无关）| **常量 1** |
| **`io` 输入** | `io_rdata` | **1** | **`rd`** ⭐ | **常量 1** |
| **`io` 输出** | X | **0** | **`rd`** | **常量 1** |
| **`bner0`** | X | **0** | **`0`** ⭐ | **`offset8` 或 常量 1** |

**—— 整个 CPU 就是「5 个选择点 + 1 个译码器」**

## 四、模块设计

### 4.1 PC（程序计数器）

**功能**：存"当前执行到第几条"

| 端口 | 方向 | 位宽 |
| --- | :-: | :-: |
| `pc_next` | 输入 | 8 |
| `clock` | 输入 | 1 |
| `pc_out` | 输出 | 8 |

**实现**：**1 个 8 位 `Register`**

**⚠️ 设计决策**：**PC 的"更新逻辑"（+1 或 +offset）不放在模块内，放顶层** ——
**因为 F5 阶段 2 → 阶段 3 时，PC 模块一行都不用改** ✅

### 4.2 ROM（指令存储器）

**规格**：**256 × 8**（`Address Bit Width = 8`、`Data Bit Width = 8`）

**只读** —— 没有时钟、没有写使能。

**内容**（「1+2+…+10」）：

| 地址 | Hex | 汇编 |
| :-: | :-: | --- |
| `00` | `8a` | `li r0, 10` |
| `01` | `90` | `li r1, 0` |
| `02` | `a0` | `li r2, 0` |
| `03` | `b1` | `li r3, 1` |
| `04` | `17` | `add r1, r1, r3` |
| `05` | `29` | `add r2, r2, r1` |
| `06` | `d1` | `bner0 r1, 4` |
| `07` | `df` | `bner0 r3, 7` |

### 4.3 dec（指令译码器）⭐

**功能**：**把 8 位指令翻译成控制信号** —— **整个 CPU 的"大脑"**

**输入**：`instr`（8 位）

**输出**（**10 个**）：

| 输出 | 位宽 | 实现 |
| --- | :-: | --- |
| `is_add` | 1 | **2-4 译码器的 `Y0`** |
| `is_io` | 1 | **`Y1`**（F6 新增）|
| `is_li` | 1 | **`Y2`** |
| `is_bner0` | 1 | **`Y3`** |
| `rd` | 2 | Splitter #1 输出 2 |
| `rs1` | 2 | Splitter #1 输出 1 |
| `rs2` | 2 | Splitter #1 输出 0 |
| `imm` | 2 | Splitter #2 输出 0（F6 从 4 位变 2 位）|
| `s` | 2 | Splitter #2 输出 1（F6 新增）|
| `offset` | 4 | Splitter #3 输出 1（F6 改名）|
| `io_dir` | 1 | Splitter #4 输出 1（F6 新增）|
| `idx` | 3 | Splitter #4 输出 0（F6 新增）|

**⭐ 设计要点：用「2-4 译码器」而不是「比较器」**

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **比较器** | 直观 | **每条指令一个比较器，指令多了元件爆炸** |
| **2-4 译码器** ✅ | **输出独热码，天然是控制信号** | 操作码稀疏时浪费一些输出 |

**讲义原话**：

> 「要识别输入的取值，最适合的电路就是**译码器**！由于 `opcode` 只有 2 位，我们可以使用一个 **2-4 译码器**，
> 它输出的**独热码**可以指示当前指令属于何种指令，这样的译码器称为**指令译码器**。
> 这组独热码通常作为**控制信号**，用于控制部分电路如何工作。」

### 4.4 gpr（通用寄存器组）⭐⭐

**功能**：**4 个 8 位寄存器 + 2 个读口 + 1 个写口** —— 即"双端口 RAM"

| 端口 | 方向 | 位宽 |
| --- | :-: | :-: |
| `raddr1` | 输入 | 2 |
| `rdata1` | 输出 | 8 |
| `raddr2` | 输入 | 2 |
| `rdata2` | 输出 | 8 |
| `waddr` | 输入 | 2 |
| `wdata` | 输入 | 8 |
| `wen` | 输入 | 1 |
| `clock` | 输入 | 1 |

**内部结构**：

```
raddr1 ──→ [MUX1 4选1] ──→ rdata1
                ↑
       ┌────────┬───┴───┬────────┐
       ↓        ↓       ↓        ↓
     [A0]     [A1]    [A2]     [A3]
       ↑        ↑       ↑        ↑
       └────────┴───┬───┴────────┘
                    ↑
                  wdata（广播给 4 个 D）
                  
       waddr → 2-4 译码器 → Y0~Y3
               Y_i · wen → 与门 → Reg_i 的 WE
               
raddr2 ──→ [MUX2 4选1] ──→ rdata2
```

**⭐ 设计要点：写使能译码**

```
waddr = 2（10）
  → 译码器 Y2 = 1
  → Y2 · wen = 1
  → 只有 Reg2 的 WE = 1
  → 时钟沿：只有 Reg2 写入 wdata  ✅
```

**—— 4 个寄存器都"看到"了 `wdata`，但只有 WE=1 的那个会存下来** ✅

### 4.5 ALU（算术逻辑单元）

**功能**：8 位加法器

| 端口 | 方向 | 位宽 |
| --- | :-: | :-: |
| `RegA` | 输入 | 8 |
| `RegB` | 输入 | 8 |
| `result` | 输出 | 8 |
| `Carry` | 输出 | 1 |

**⚠️ 设计陷阱**：原电路还有 `Dout`（经三态缓冲器）—— **两个 8 位输出如果都接到同一处会冲突（红线）** → **只用 `result`** ✅

### 4.6 比较器（Cmp）

**功能**：比较两个 8 位数（`bner0` 用）

| 端口 | 接 |
| --- | --- |
| `A` | `gpr.rdata1`（**`bner0` 时 = `R[0]`**）|
| `B` | `gpr.rdata2`（= `R[rs2]`）|
| **`=`** | **经 NOT 门 → `bne`** |

### 4.7 io 外设（F6 新增）

| 设备 | 类型 | 实现 |
| --- | --- | --- |
| **LED**（8 个）| 输出 | `led_reg`（8 位 Register）+ 8 个 LED |
| **七段数码管** | 输出 | `seg7_reg` + `seg7` 子电路（ROM 查表）|
| **拨码开关**（8 个）| 输入 | 8 个 `Pin` + Splitter 合并 |
| **按钮**（8 个）| 输入 | 8 个 `Pin` + Splitter 合并 |

**设备关联**（讲义指定）：

| `i/o` | `idx` | 设备 |
| :-: | :-: | --- |
| **1** | `000` | **输出到 LED** |
| **1** | `001` | **输出到七段数码管** |
| **0** | `000` | **从拨码开关输入** |
| **0** | `001` | **从按钮输入** |

## 五、F5 实现过程

### 5.1 阶段 1：只支持 `li`

**目标**：验证"取指 → 译码 → 写寄存器 → 更新 PC"这条链路

**部件**：

| 部件 | 实现 |
| --- | --- |
| PC | 8 位 Register + 计数器 |
| ROM | 256 × 8 |
| 译码 | 3 个 Splitter 拆 opcode / rd / imm |
| GPR | 4 个 8 位 Register + decoder24 |
| `wen` | 常量 1 |

**验证**：

| 拍 | PC | r0 | r1 | r2 | r3 |
| :-: | :-: | :-: | :-: | :-: | :-: |
| 1 | 1 | **5** | 0 | 0 | 0 |
| 2 | 2 | 5 | **3** | 0 | 0 |
| 3 | 3 | 5 | 3 | **7** | 0 |
| 4 | 4 | 5 | 3 | 7 | **1** |

**—— 4 条 `li` 全对** ✅

### 5.2 阶段 2：加 `add`

**新增**：

| 部件 | 作用 |
| --- | --- |
| **2-4 译码器** | opcode → `is_add` / `is_li` / `is_bner0` |
| **GPR 双读口** | 同时读 `rs1`、`rs2` |
| **加法器** | `rdata1 + rdata2` |
| **`MUX_wdata`** | `is_add ? alu.result : imm8` |
| **`wen`** | `is_add OR is_li` |

**验证**：

| 拍 | PC | r0 | r1 | r2 | r3 |
| :-: | :-: | :-: | :-: | :-: | :-: |
| 4 | 4 | 10 | 0 | 0 | **1** |
| **5** | 5 | 10 | **1** | 0 | 1 |
| **6** | 6 | 10 | 1 | **1** | 1 |

**—— 第 5、6 拍算出 1** ✅

### 5.3 阶段 3：加 `bner0`

**新增**：

| 部件 | 作用 |
| --- | --- |
| **`MUX_raddr1`** | **`is_bner0 ? 0 : rs1`** ⭐ |
| **比较器** | 比较 `R[0]` 和 `R[rs2]` |
| **`pc_taken`** | `is_bner0 AND bne` |
| **`MUX_pc`** | 选 `PC+1` 或 `addr` |

**最终验证**（「1+2+…+10」）：

| 阶段 | PC 轨迹 | r1 | r2 |
| --- | --- | :-: | :-: |
| 初始化 | 0→1→2→3→4 | 0 | 0 |
| 循环 1 | 4→5→6→**4** | 1 | 1 |
| 循环 2 | 4→5→6→**4** | 2 | 3 |
| … | … | … | … |
| 循环 10 | 4→5→6→**7** | 10 | **55** |
| 停机 | 7→7→7… | 10 | 55 |

**—— 最终 `PC=7`、`R[2]=55`** ✅

## 六、F6 实现过程

### 6.1 `li` 的 `s` 字段

**实现**：**`Shifter`（移位器）**

```
imm（2 位）→ Bit Extender（Zero，2→8）→ Shifter（左移 s*2）→ imm8
                                          ↑
                                     s*2（Splitter 拼接 {s, 0}）
```

**验证**（4 条 li，`imm` 都是 `11`）：

| 拍 | 机器码 | `s` | `r0` |
| :-: | :-: | :-: | :-: |
| 1 | `83` | `00` | **3** |
| 2 | `87` | `01` | **12** |
| 3 | `8b` | `10` | **48** |
| 4 | `8f` | `11` | **192** |

**—— 4 种 `s` 全对** ✅

### 6.2 `bner0` 的 `offset`

**实现**：

| 改动 | 内容 |
| --- | --- |
| **Bit Extender** | **`Type` 改成 `Sign Extend`**（4→8）|
| **`MUX_addB`** | **新增**：`D0=常量1`、`D1=offset8`、`S=pc_taken` |
| **`MUX_pc`** | **删除**（加法器直接接 PC）|

**F5 vs F6 的结构**：

```
F5：Adder_pc(PC+1) → MUX_pc(选 PC+1 或 addr) → PC
F6：MUX_addB(选 1 或 offset8) → Adder_pc → PC
```

**—— 一个加法器干两件事** ✅

### 6.3 `io` 指令

**`dec` 新增 3 个输出**：

| 输出 | 位宽 | 实现 |
| --- | :-: | --- |
| `is_io` | 1 | **2-4 译码器的 `Y1`**（F5 时空的）|
| `io_dir` | 1 | **Splitter #4 的 bit 3** |
| `idx` | 3 | **Splitter #4 的 bit 2~0** |

**`MUX_raddr1` 从 2 选 1 → 3 选 1**（**最隐蔽的坑**）：

```
D0 ← rs1            （add）
D1 ← 常量 0          （bner0）
D2 ← rd             （io）⭐
S  = {is_io, is_bner0}
```

**`MUX_wdata` 从 2 选 1 → 3 选 1**：

```
D0 ← imm8          （li）
D1 ← alu.result    （add）
D2 ← io_rdata      （io 输入）⭐
S  = {S1, S0}，S1 = is_io AND NOT io_dir
```

**`wen` 加一路**：

```
wen = is_add OR is_li OR (is_io AND NOT io_dir)
```

### 6.4 设备实现

**LED**：

```
led_reg（8 位 Register）
  D   ← gpr.rdata1
  WE  ← is_io AND io_dir AND (idx == 000)
  Q   → 8 个 LED
```

**七段数码管**：

```
seg7_reg（8 位 Register）
  WE  ← is_io AND io_dir AND (idx == 001)
  Q   → 低 4 位 → seg7_rom（4→7）→ 7 个段
```

**输入 MUX**：

```
io_rdata = idx[0] ? 按钮 : 拨码开关
```

### 6.5 验证

**程序**（最终演示）：

| 地址 | Hex | 汇编 |
| :-: | :-: | --- |
| `00` | `40` | `in r0, 拨码` |
| `01` | `48` | `out r0, LED` |
| `02` | `49` | `out r0, 七段` |
| `03` | `F7` | `bner0 r3, -3`（跳回 0）|

**效果**：**拨码一变，LED 和数码管同步跟着变** ✅

## 七、⭐ 设计亮点

> **这一章是答辩的核心。下面 8 个亮点，每一个都能讲 1~2 分钟。**

### 亮点 1：控制信号表驱动设计 ⭐⭐⭐

**做法**：**先把"每条指令要做什么"列成一张表，再用 MUX 实现每一列。**

**讲义原文的表**（F5 版）：

| 指令 | `wdata` 的选择 | `wen` | `raddr1` 的选择 | 更新 PC 的选择 |
| :-: | --- | :-: | --- | --- |
| **`add`** | 加法器的输出 | 1 | 指令的 `rs1` | `PC + 1` |
| **`li`** | 立即数 | 1 | X（无关）| `PC + 1` |
| **`bner0`** | X | **0** | **`0`** | 指令的 `addr` |

**我的扩展**（F6 版加了 `io`）：

| 指令 | `wdata` | `wen` | `raddr1` | 加法器 B 端 |
| :-: | --- | :-: | --- | --- |
| **`io` 输入** | `io_rdata` | **1** | **`rd`** | 常量 1 |
| **`io` 输出** | X | **0** | **`rd`** | 常量 1 |

**为什么这是亮点**：

> **这张表把"指令语义"和"电路结构"彻底分离了**：
> - **表里每一列 = 一个 MUX 的选择逻辑**
> - **加新指令 = 在表里加一行 + MUX 加一路**
>
> **—— 这就是"用指令控制电路"的具体做法**，也是讲义的核心思想。

### 亮点 2：一个 MUX 解决"读谁"的问题（`MUX_raddr1` 三路复用）⭐⭐⭐

**问题演进**：

| 阶段 | 需求 | 解法 |
| --- | --- | --- |
| **F5 阶段 2** | `add` 读 `rs1` | `raddr1` 直接接 `rs1` |
| **F5 阶段 3** | `bner0` 要读 `R[0]` | **加 MUX：`is_bner0 ? 0 : rs1`** |
| **F6** | `io` 要读 `R[rd]` | **MUX 再加一路：`rd`** |

**最终结构**：

```
MUX_raddr1（Select Bits=2，Data Bits=2）
  D0 ← rs1            （add）
  D1 ← 常量 0          （bner0）
  D2 ← rd             （io）⭐
  S  = {is_io, is_bner0}
```

| `is_io` | `is_bner0` | `S` | 读到 |
| :-: | :-: | :-: | --- |
| 0 | 0 | `00` | **R[rs1]** |
| 0 | 1 | `01` | **R[0]** |
| **1** | X | `1X` | **R[rd]** ⭐ |

**为什么这是亮点**：

> **GPR 只有 2 个读口** —— 但**不同指令要读不同的寄存器**：
> - `add` 读 `rs1` / `rs2`
> - `bner0` 读 `R[0]` / `rs2`
> - `io` 读 `R[rd]`
>
> **一个 2 位的 MUX 就解决了「三种指令共用两个读口」的问题** ——
> **没有增加 GPR 的端口，只加了一个 MUX** ✅
>
> **—— 这就是"复用硬件"的典型手法。**

### 亮点 3：加法器复用 ⭐⭐

**讲义原话**：

> 「之前为了计算 PC+1，已经使用了一个加法器，考虑到 `bner0` 指令跳转时，**并不需要计算 PC+1**，
> 因此可以考虑**让跳转目标的计算复用这个加法器**。」

**F5 的做法**（2 个 MUX 串联）：

```
PC ──→ Adder_pc(+1) ──→ MUX_pc ──→ PC
                          ↑
                        addr8
```

**F6 的做法**（1 个 MUX 在加法器 B 端）：

```
              ┌─────────────┐
              │  MUX_addB   │ ← pc_taken
              │ D0=1, D1=off│
              └──────┬──────┘
                     ↓
PC ──→ Adder_pc(PC + X) ──→ PC
```

**为什么这是亮点**：

> **一个加法器 + 一个 MUX，同时实现了「PC+1」和「PC+offset」** ——
> **比"两个加法器 + 一个 MUX"省了一半硬件** ✅
>
> **而且「不加新加法器，只在输入端加 MUX」这个思路，可以推广到所有"复用 ALU"的场景**（比如 RISC-V 的 ALU 同时做加减与或）。

### 亮点 4：指令编码的"位数腾挪" ⭐⭐

**`li` 的演进**：

| 版本 | 编码 | 能装 |
| --- | :-: | :-: |
| **F5** | `10 + rd(2) + imm(4)` | **0~15** |
| **F6** | `10 + rd(2) + s(2) + imm(2)` | **0~192**（4 种移位）|

**关键洞察**：

> **`imm` 从 4 位变 2 位（更少了），但加上 `s` 后能表示的数更多了** ——
>
> | 方案 | 能表示的数 | 指令条数（装 192）|
> | --- | --- | :-: |
> | **4 位 imm** | 0~15（16 个）| **7 条** |
> | **2 位 s + 2 位 imm** | 0~192（16 个，但分布到 4 个段）| **1 条** ✅ |
>
> **—— 同样 4 位，换个解释方式，效率提升 7 倍。**
>
> **这就是"指令编码"的艺术：位数有限，但"解释方式"无限。**

**而且这还体现了「稀疏编码」的思想**：`s=01` 时能装 0/4/8/12 —— **不是连续的，但覆盖了需要的场景**（比如"步长 4 的倍数"）。

### 亮点 5：输出设备必须"锁存" ⭐⭐

**问题**：

> `io` 指令**只持续 1 个时钟周期** ——
> **如果直接连 LED，LED 只亮一个周期**（肉眼看不见，看起来像"没反应"）❌

**解法**：

```
gpr.rdata1 ──→ [led_reg: Register] ──→ LED
                    ↑
              WE = is_io · io_dir · (idx==000)
```

**为什么这是亮点**：

> **"锁存"把「瞬时信号」变成「持续输出」** ——
> **这正是真实硬件的做法**：真实 CPU 的 IO 端口也是"写寄存器"（比如 x86 的 `out` 指令写端口寄存器）。
>
> **—— 而且这个 Register 只用一个 WE 信号控制，和 GPR 的写法完全一样**（复用同一套"写使能译码"模式）✅

### 亮点 6：模块化 + 可独立验证 ⭐⭐

**设计原则**：

| 原则 | 体现 |
| --- | --- |
| **每个模块可单独测** | `dec` 单独测 3 种指令；`gpr` 单独测写入/读出；`seg7` 单独测段码 |
| **模块边界清晰** | `gpr` / `dec` / `pc` / `ALU` 各自独立子电路 |
| **改动局部化** | **F5 → F6 只改了 `dec` + 顶层**，`gpr`/`ALU`/`pc` 完全没动 |

**为什么这是亮点**：

> **F6 的改动量 = F5 的 1/3** ——
> **因为 F5 的设计把"变的部分"（指令译码）和"不变的部分"（寄存器堆、ALU）分开了**。
>
> **—— 好的模块划分，让"扩展"变成"局部修改"，而不是"推倒重来"** ✅

### 亮点 7：从"能算"到"能交互" ⭐⭐⭐

**三个阶段的能力跃迁**：

| 阶段 | 能做什么 | 局限 |
| --- | --- | --- |
| **F5 阶段 1** | 装立即数 | 只能看寄存器 |
| **F5 阶段 3** | 循环、求和 | 只能看寄存器 |
| **F6** | **读拨码、写 LED/数码管** | **能跟人交互** ✅ |

**为什么这是亮点**：

> **讲义原话**：
> > 「在**真实的处理器芯片**中，我们**很难直接观察芯片内部的状态**。
> > 事实上，用户通常是**通过输入输出方式**与处理器芯片进行交互。」
>
> **加了 `io` 之后，sCPU 从"教学演示电路"变成了"有实用接口的处理器"** ——
> **你可以拨开关、看灯亮** —— **这才像一台"机器"** ✅

### 亮点 8：调试方法论（可复用的经验）⭐⭐

**我在整个项目中总结出 4 条调试方法**：

| # | 方法 | 例子 |
| :-: | --- | --- |
| **1** | **Probe 逐级排查** | `ROM.输出 → imm → opcode → li_en → 寄存器 WE`，哪级不对修哪级 |
| **2** | **子电路先单独验证** | `gpr` / `dec` / `seg7` 各自在子电路页里测通了才拼顶层 |
| **3** | **用"已知输入"反推接线错误** | 实验三调七段码时，用"显示 1 应该只有 b、c 亮"反推段序 |
| **4** | **"u"（高阻）是最容易定位的错误** | 显示 `u` = 那根线没接任何驱动，直接去看那个引脚 |

**还有一个"血的教训"**：

> **Probe 接在子电路方块的「输入侧」还是「输出侧」，结果完全不同** ——
> **输入侧看到的是"外部信号"，输出侧才是"模块内部状态"** ⚠️
>
> **我在这上面卡了很久**（`r1`/`r2` 一直显示 `u`，最后发现 Probe 接在了 `gpr` 的输入引脚上）。

## 八、调试方法论（详细记录）

### 8.1 问题清单

| # | 问题 | 根因 | 修复 |
| :-: | --- | --- | --- |
| 1 | 寄存器全是 0 | ROM 内容填成了二进制字符串 | 改填十六进制 |
| 2 | 寄存器全是 0 | 缺 Splitter 拆 opcode | 加 Splitter |
| 3 | 全加器输出全蓝 | 子电路引脚 `Output?` 没设 | 改成 `Yes` |
| 4 | `li_en` 被拉低 | `mux41` 的 `S0` 被设成输出 | 删掉多余引脚 |
| 5 | 红线 | 长绕线"路过"了输出引脚 | 改用 Tunnel |
| 6 | 红线 | Tunnel 重名 | 改名 |
| 7 | `add` 不写 GPR | `gpr` 内部与门 In2 接错 | 接到 `wen` |
| 8 | `r1`/`r2` 显示 `u` | **Probe 接在 `gpr` 的输入侧** ⭐ | 改接到输出侧 |
| 9 | `r0` = 255 | **`MUX_wdata.D0` 接成了 `offset8`** ⭐ | 改接 `imm8` |
| 10 | `bne` 红线 | 反馈环 | 检查 Tunnel |
| 11 | 循环跳错 | `bner0` 的 offset 算成了绝对地址 | 改成"目标 − 当前" |
| 12 | `in` 读到错值 | **`MUX_raddr1` 没加 `rd` 一路** ⭐ | 改成 3 选 1 |

### 8.2 最有效的 3 个调试技巧

**技巧 1：静态检查优先**

```
打拍前，先确认 PC=0 时这 9 个信号：
  instr / is_x / rd / rs1 / rs2 / raddr1 / wen / MUX.S / wdata
—— 9 个全对，再打拍
```

**—— 能提前发现 80% 的问题** ✅

**技巧 2：从"输出"往"输入"逐级查**

```
现象：r1 不对
  → 查 gpr.wdata（写进去的是不是 1）
    → 查 MUX_wdata.Y（MUX 选的是不是 D1）
      → 查 MUX_wdata.S（S 是不是 01）
        → 查 is_add（是不是 1）
          → 查 dec（译码对不对）
```

**—— 第一个"不对"的地方就是问题所在** ✅

**技巧 3：用"极端数据"测**

```
❌ 用 add r1, r1, r3（0 + 1 = 1）—— 变化太小看不出
✅ 用 add r3, r1, r2（3 + 5 = 8）—— 一眼看出
```

## 十一、总结与展望

### 11.1 总结

**这个项目让我真正理解了这句话**：

> 「**在 CPU 上执行程序 = 用指令序列控制电路进行状态转移。**」

**具体来说**：

1. **"指令"就是"控制信号"的编码** —— 译码器把 8 位指令变成若干条 0/1 信号
2. **"执行"就是"数据流动"** —— MUX 根据控制信号决定数据往哪流
3. **"状态"就是"寄存器"** —— PC 和 GPR 是唯一跨周期保存的东西

### 11.2 三个"最深的体会"

| # | 体会 |
| :-: | --- |
| **1** | **位数有限，但"解释方式"无限** —— `li` 的 4 位从"4 位立即数"变成"2 位 s + 2 位 imm"，效率提升 7 倍 |
| **2** | **复用胜于堆硬件** —— 一个加法器 + 一个 MUX，同时实现 PC+1 和 PC+offset |
| **3** | **观察方式决定调试效率** —— Probe 接错边（输入 vs 输出）会浪费几小时 |

### 11.3 展望

| 方向 | 内容 |
| --- | --- |
| **更多设备** | `idx` 有 3 位，能连 8 个设备（现在只用了 2 个）|
| **中断** | 不用轮询，设备主动通知 CPU |
| **流水线** | 讲义「迈向现代化的处理器设计」的方向 |
| **加分项** | **v24.07 的 F6：从零搭一个 32 位 RISC-V 处理器（minirv）** |
