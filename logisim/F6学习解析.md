## 一、F6 到底加了什么

### F5 能干的事

```
程序：1+2+…+10
结果：PC = 7，R[2] = 55
```

**但 F5 有三个「硬伤」**（讲义原文）：

| 局限 | 后果 |
| --- | --- |
| **`li` 只能装 `0~15`** | 装 192 要 **1 条 li + 6 条 add** |
| **`bner0` 只能跳到 `0~15`**（绝对地址）| 程序一大就跳不到 |
| **没有输入输出** | **只能"跑完看寄存器"，没法跟人交互** |

### F6 的三个解法

| 问题 | F6 的解法 |
| --- | --- |
| `li` 装不了大数 | **加 `s` 字段（移位）** |
| `bner0` 跳不远 | **改成 `offset`（相对偏移）** |
| 没有输入输出 | **加 `io` 指令 + 4 个设备** |

> **一句话**：**F5 解决"能不能算"，F6 解决"好不好用"和"能不能交互"** ✅

## 二、sISA v3.0：四条指令

**F5 有 3 条，F6 变成 4 条**：

```
 7  6 5  4 3   2 1   0
+----+----+---+-------+
| 00 | rd | rs1 | rs2 |    R[rd] = R[rs1] + R[rs2]           add
+----+----+---+-------+
| 01 | rd |i/o|  idx  |    R[rd] <=> dev[idx]          io（新增）
+----+----+---+-------+
| 10 | rd | s |  imm  |    R[rd] = imm << (s << 1)           li（改）
+----+----+---+-------+
| 11 |  offset  | rs2 |    if (R[0] != R[rs2])              bner0（改）
|                     |        PC = PC + sign_ext(offset)
+----+----------+-----+
```

### ⭐ 一个值得讲的设计点

**`01` 是 F5 里唯一空着的操作码槽位** —— **F6 正好用它加 `io`**。

> **这说明 ISA 设计要「留扩展空间」**：
> **2 位 opcode 有 4 个值，F5 只用了 3 个，**空的第 4 个后面刚好能加新指令** ✅

**答辩时可以提**：这就是"指令集设计的前瞻性"。

## 三、`li` 的 `s` 字段：一条指令装大数

### 3.1 问题：F5 装 192 要 7 条指令

**F5 的 `li`**：`imm` 只有 4 位 → **只能装 0~15**

**装 192（`11000000`）**：

```
0: li r0, 3
1: add r0, r0, r0   # 6
2: add r0, r0, r0   # 12
3: add r0, r0, r0   # 24
4: add r0, r0, r0   # 48
5: add r0, r0, r0   # 96
6: add r0, r0, r0   # 192
```

**—— 7 条指令，只为了装一个常数** ❌

### 3.2 F6 的解法：`2 位 imm` + `2 位 s`

```
 7  6 | 5  4 | 3  2 | 1  0
+-----+------+------+------+
| 10  |  rd  |  s   | imm  |
+-----+------+------+------+

R[rd] = imm << (s << 1)
```

**`s` 表示「把 imm 放在 8 位的哪一段」**：

| `s` | 8 位布局 | `imm=11`（=3）时 |
| :-: | :-: | :-: |
| `00` | `00 00 00 imm` | **3** |
| `01` | `00 00 imm 00` | **12** |
| `10` | `00 imm 00 00` | **48** |
| `11` | `imm 00 00 00` | **192** |

**—— 装 192 只要 1 条**：`1000 1111` = `8F` ✅

### 3.3 怎么理解 `imm << (s << 1)`

**`s << 1`** = **`s` 乘以 2**（因为 `imm` 是 2 位，每移"一段"要移 2 位）

| `s` | `s << 1` = 移位量 |
| :-: | :-: |
| `00` | **0** |
| `01` | **2** |
| `10` | **4** |
| `11` | **6** |

**例子**：

```
imm = 3（11）、s = 10（2）
→ 移位量 = 2 << 1 = 4
→ imm8 = 3 << 4 = 48  ✅
```

### 3.4 电路怎么实现（答辩要点）

**讲义原话**：

> 「我们可以将 `s` 字段看成一个**选择信号**，来从 4 种立即数当中选择一种，
> 每一种立即数对应了将 `imm` 放置在某一段位置的情况。
> 从这个角度来看，**使用多路选择器**就可以实现 `li` 指令的功能。」

**两种实现**：

| 方案 | 元件 | 说明 |
| --- | --- | --- |
| **讲义建议** | **4 选 1 MUX + 4 个移位常量** | 直观，但元件多 |
| **我用的** | **`Shifter`（移位器）** | **1 个元件 + 1 个 `s*2` 拼接** ✅ |

**我的电路**：

```
imm（2 位）
  ↓
Bit Extender（Zero Extend，2→8）
  ↓
Shifter（Data Bits=8，Logical Left）
  ↑ 移位量 = s*2（3 位）
  ↓
imm8
```

**`s*2` 怎么来**：**用 `Splitter`（Facing=West）拼接** `{s, 1'b0}`

**答辩可以提**：

> **讲义说"用 MUX"，我用 `Shifter`，本质一样**（都是按 `s` 选移位量），
> **但 `Shifter` 更省元件** —— **理解了原理后，实现方式可以自由选择** ✅

## 四、`bner0` 的 `offset`：相对跳转

### 4.1 问题：F5 只能跳 `0~15`

**F5 的 `bner0`**：

```
| 11 | addr(4位) | rs2 |
PC = addr          ← 绝对地址
```

**—— 只能跳到地址 `0~15`** ❌

### 4.2 F6 的解法：`offset`（相对偏移）

```
| 11 | offset(4位) | rs2 |
PC = PC + sign_ext(offset)
```

**`offset` = "相对当前 PC 的偏移"**：

| 想跳到 | `offset`（4 位补码）| Hex |
| --- | :-: | :-: |
| **下一条（+1）** | `0001` | `1` |
| **上一条（-1）** | `1111` | `F` |
| **-3** | `1101` | `D` |
| **+7** | `0111` | `7` |

**范围**：**-8 ~ +7** ✅

### 4.3 ⭐ 关键：**符号扩展（Sign Extend）**

**4 位 `offset` 要扩展成 8 位**（因为 PC 是 8 位）—— **两种方式**：

| 方式 | `1111` 扩展成 | 真值 | 对不对 |
| --- | :-: | :-: | :-: |
| **零扩展**（高位补 0）| `00001111` | **+15** | ❌ |
| **符号扩展**（高位补符号位）| `11111111` | **-1** | ✅ |

**讲义原话**：

> 「在补码中，对于负数，进行零扩展前后，**真值会发生变化**。
> 例如，4 位补码 `0b1111` 的真值是 `-1`，对其进行零扩展后得到 5 位补码 `0b01111`，真值是 `15`。
> **为了保证扩展后 `offset` 的真值保持不变，`bner0` 指令需要对 `offset` 进行符号扩展。**」

**—— 所以 `bner0` 的 `Bit Extender` 必须设 `Type = Sign Extend`** ⚠️

**对照记忆**：

| 数据 | 有符号吗 | 扩展方式 |
| --- | :-: | :-: |
| **`li` 的 `imm`** | **无符号**（0~3）| **Zero Extend** |
| **`bner0` 的 `offset`** | **有符号**（-8~+7）| **Sign Extend** ⭐ |

### 4.4 ⭐ 复用加法器（讲义的巧妙之处）

**讲义原话**：

> 「之前为了计算 **PC+1**，已经使用了一个加法器，考虑到 `bner0` 指令跳转时，
> **并不需要计算 PC+1**，因此可以考虑**让跳转目标的计算复用这个加法器**。
> 但为了复用它，你需要考虑如何添加**额外的控制信号**。」

**F5 的结构**（2 个 MUX 串联）：

```
PC.Q → Adder_pc(PC+1) → MUX_pc(选 PC+1 或 addr) → PC
```

**F6 的结构**（1 个 MUX 在加法器 B 端）：

```
MUX_addB(选 常量1 或 offset8) → Adder_pc(PC + 它) → PC
```

**—— 一个加法器干两件事** ✅

**对照**：

| `pc_taken` | 加法器 B 端 | 加法器算 | 结果 |
| :-: | --- | --- | --- |
| **0** | 常量 1 | **PC + 1** | 顺序执行 |
| **1** | `offset8` | **PC + offset** | 跳转 |

**⚠️ `pc_taken` = `is_bner0 AND bne`** ——
**不能只接 `is_bner0`**，否则 `bner0` 但"相等"时也会偏移（错的）⚠️

## 五、`io` 指令：处理器怎么跟外界说话

### 5.1 为什么需要输入输出

**讲义原话**：

> 「为了检查运行结果，你是**直接观察 PC 寄存器和 GPR 的值**。
> 但在**真实的处理器芯片**中，我们**很难直接观察芯片内部的状态**。
> 事实上，用户通常是**通过输入输出方式**与处理器芯片进行交互。」

**—— 真实 CPU 靠"读外设、写外设"跟人交流**（键盘、屏幕、LED…）

### 5.2 `io` 指令的格式

```
 7  6 | 5  4 | 3 | 2  1  0
+-----+------+---+---------+
| 01  |  rd  |i/o|   idx   |
+-----+------+---+---------+

R[rd] <=> dev[idx]
```

| 字段 | 位置 | 位宽 | 含义 |
| --- | :-: | :-: | --- |
| **`opcode`** | bit 7~6 | 2 | **`01`** |
| **`rd`** | bit 5~4 | 2 | 寄存器 |
| **`i/o`** | **bit 3** | **1** | **0 = 输入，1 = 输出** |
| **`idx`** | **bit 2~0** | **3** | **设备编号（0~7）** |

**行为**：

| `i/o` | 操作 | 数据流向 | 类比 |
| :-: | --- | --- | --- |
| **0** | **输入** | **`dev[idx]` → `R[rd]`** | **"读开关"** |
| **1** | **输出** | **`R[rd]` → `dev[idx]`** | **"点 LED"** |

**—— 一条指令，两个方向，靠 1 位切换** ✅

### 5.3 指令编码速查

| 汇编（示意）| 二进制 | Hex |
| --- | :-: | :-: |
| **`in r0, 拨码`** | `01 00 0 000` | **`40`** |
| **`in r1, 按钮`** | `01 01 0 001` | **`51`** |
| **`out r0, LED`** | `01 00 1 000` | **`48`** |
| **`out r2, 七段`** | `01 10 1 001` | **`69`** |

**记忆技巧**：**`40` 和 `48` 只差 bit 3** —— **那就是 `i/o` 位** ✅

### 5.4 ⚠️⭐ 最隐蔽的设计点：**`rd` 的位段**

**`io` 的 `rd` 在 bit 5~4** —— 但 **`gpr.raddr1` 平时接的是 `rs1`（bit 3~2）**！

```
add:  | 00 | rd(5~4) | rs1(3~2) | rs2(1~0) |
io :  | 01 | rd(5~4) | i/o(3)   | idx(2~0) |
              ↑
          io 要读的是 bit 5~4，不是 bit 3~2！
```

**→ 必须给 `MUX_raddr1` 再加一路 `rd`** ⭐

**改完后的 `MUX_raddr1`**：

```
MUX_raddr1（Select Bits=2，Data Bits=2）
  D0 ← dec.rs1            （add）
  D1 ← 常量 0              （bner0，读 R[0]）
  D2 ← dec.rd             （io，读 R[rd]）⭐
  D3 ← 常量 0
  S  = {is_io, is_bner0}
  Y  → gpr.raddr1
```

| `is_io` | `is_bner0` | `S` | 选中 | 读到 |
| :-: | :-: | :-: | --- | --- |
| 0 | 0 | `00` | `rs1` | **R[rs1]**（add）|
| 0 | 1 | `01` | `0` | **R[0]**（bner0）|
| **1** | X | `1X` | **`rd`** | **R[rd]**（io）⭐ |

**—— 这是 F6 最隐蔽的坑**（答辩可以主动提，显示想得深）✅

## 六、设备：LED / 七段 / 拨码 / 按钮

### 6.1 设备关联表（讲义指定）

| `i/o` | `idx` | 设备 |
| :-: | :-: | --- |
| **1** | `000` | **输出到 LED** |
| **1** | `001` | **输出到七段数码管** |
| **0** | `000` | **从拨码开关输入** |
| **0** | `001` | **从按钮输入** |

**讲义要点**：

> 「通常**不会从 LED 输入**，也**不会输出到拨码开关**，因此可以让它们**复用同一个设备编号 `0b000`**。」

**—— 4 个设备，2 个编号，靠 `i/o` 位区分** ✅

### 6.2 ⭐ 输出设备必须"锁存"

**问题**：**`io` 指令只持续 1 拍** ——
**如果不锁存，LED 只亮一个时钟周期**（肉眼根本看不见）❌

**解法**：**用 8 位 Register 锁存**

```
gpr.rdata1（= R[rd]）
    ↓
┌─────────────────┐
│    led_reg      │  ← 8 位 Register
│  WE = is_io     │
│     AND io_dir  │
│     AND (idx==000)
└────────┬────────┘
         ↓ Q（8 位）
    Splitter（8→8）
         ↓
  LED0 LED1 … LED7
```

**—— "锁存"是输出设备的关键**（答辩可以提）✅

### 6.3 输入设备"不需要锁存"

**因为**：**拨码开关的状态"一直有效"** ——
**CPU 每次执行 `in` 指令就重新读一次** ✅

```
拨码开关（8 个 Pin）
    ↓ Splitter 合并
             ┌──────────────┐
             │  2 选 1 MUX  │ ← S = idx[0]
             └──────┬───────┘
                    ↓
              io_rdata（8 位）
                    ↑
按钮（8 个 Pin）→ Splitter 合并
```

### 6.4 七段数码管：需要"译码"

**问题**：**7 个段（a~g）要显示数字** —— **需要"数字 → 段码"的映射**

**解法**：**用 ROM 存"段码表"**（实验三做过的 `seg7_rom`）

```
data（4 位）→ ROM（4→7）→ Splitter（7→7）→ a~g
```

**ROM 内容**（0~9）：

| 地址 | 段码 | 二进制 | 显示 |
| :-: | :-: | :-: | :-: |
| 0 | `7e` | `1111110` | 0 |
| 1 | `30` | `0110000` | 1 |
| 2 | `6d` | `1101101` | 2 |
| 3 | `79` | `1111001` | 3 |
| 4 | `33` | `0110011` | 4 |
| 5 | `5b` | `1011011` | 5 |
| 6 | `5f` | `1011111` | 6 |
| 7 | `70` | `1110000` | 7 |
| 8 | `7f` | `1111111` | 8 |
| 9 | `7b` | `1111011` | 9 |

**—— 只支持 0~9**（要 A~F 得补 ROM）✅

## 七、数据通路的 5 处改动

### 改动 1：`MUX_wdata` 从 2 选 1 → 3 选 1

**F5**：

```
D0 ← imm8          （li）
D1 ← alu.result    （add）
S  ← is_add
```

**F6**：

```
D0 ← imm8          （li）
D1 ← alu.result    （add）
D2 ← io_rdata      （io 输入）⭐ 新增
D3 ← 常量 0

S（2 位）= {S1, S0}
  S1 = is_io AND NOT io_dir       （io 输入方向）
  S0 = is_add
```

**对照**：

| `S1` | `S0` | `S` | 选中 | 什么时候 |
| :-: | :-: | :-: | --- | --- |
| 0 | 0 | `00` | **`imm8`** | **li** |
| 0 | 1 | `01` | **`alu.result`** | **add** |
| **1** | X | `1X` | **`io_rdata`** | **io 输入** |
| — | — | `11` | D3（不用）| — |

**—— 三种"写回数据"靠 2 位选择** ✅

### 改动 2：`wen` 加一路

```
wen = is_add OR is_li OR (is_io AND NOT io_dir)
                          └──────┬──────┘
                             复用 S1
```

**对照**：

| 指令 | `wen` | 为什么 |
| --- | :-: | --- |
| **`add`** | **1** | 写 `R[rd]` |
| **`li`** | **1** | 写 `R[rd]` |
| **`io` 输入** | **1** | 写 `R[rd]` ✅ |
| **`io` 输出** | **0** | **只读，不写** ⭐ |
| **`bner0`** | **0** | 不写 |

**⚠️ 最容易错**：**把 `is_io` 直接接进 OR 门** →
**`io` 输出时也写 GPR**，**把 `R[rd]` 用设备输入值覆盖了** ❌

### 改动 3：`MUX_raddr1` 从 2 选 1 → 3 选 1

**（见 5.4 —— 这是最隐蔽的坑）**

### 改动 4：LED 锁存器

```
led_reg（Register，Data Bits = 8）
  D   ← gpr.rdata1（= R[rd]）
  WE  ← is_io AND io_dir AND (idx == 000)
  clk ← Clock
  Q   → Splitter（8→8）→ 8 个 LED
```

**`idx == 000` 的检测**：**3 输入 NOR 门**

```
NOR(0, 0, 0) = 1
NOR(其他)    = 0
```

**—— 一个 NOR 门就实现了"全 0 检测"** ✅

### 改动 5：七段锁存器 + 输入 MUX

**七段锁存器**：

```
seg7_reg（Register，8 位）
  D   ← gpr.rdata1
  WE  ← is_io AND io_dir AND (idx == 001)
  Q   → 低 4 位 → seg7 子电路 → 数码管
```

**`idx == 001` 的检测**：

```
NOT(idx[2]) AND NOT(idx[1]) AND idx[0]
```

**输入 MUX**：

```
io_rdata = idx[0] ? 按钮 : 拨码开关
```

| 引脚 | 接 |
| --- | --- |
| `D0` | 拨码开关（8 位）|
| `D1` | 按钮（8 位）|
| `S` | **`idx[0]`** |
| `Y` | `io_rdata` → `MUX_wdata.D2` |

**—— `idx=000`（拨码）和 `idx=001`（按钮）只差最低位** ✅

## 八、四条指令的全过程

### `li r0, 12`（机器码 `87`）

```
87 = 1000 0111
     ↑↑↑↑ ↑↑↑↑
     |||| |||└── imm = 11（3）
     |||| ||└─── s   = 01（1）
     |||| └───── rd  = 00（r0）
     └───┴───── opcode = 10（li）
```

| 步骤 | 信号 | 值 |
| :-: | --- | --- |
| **① 取指** | `PC → ROM` | PC=0，`instr = 87` |
| **② 译码** | `dec` | `is_li = 1`，`rd=0`，`s=1`，`imm=3` |
| **③ 算 imm8** | `Shifter` | `3 << (1×2)` = **12** |
| **④ 选写回数据** | `MUX_wdata` | `S = 00` → **D0 = imm8 = 12** |
| **⑤ 写 GPR** | `wen = 1` | **`R[0] = 12`** |
| **⑥ 更新 PC** | `pc_taken = 0` | `MUX_addB` 选常量1 → **PC = 1** |

---

### `add r0, r0, r0`（机器码 `03`）

```
03 = 0000 0011
     ↑↑↑↑ ↑↑↑↑
     |||| |||└── rs2 = 11（r0）
     |||| ||└─── rs1 = 00（r0）
     |||| └───── rd  = 00（r0）
     └───┴───── opcode = 00（add）
```

| 步骤 | 信号 | 值 |
| :-: | --- | --- |
| **① 取指** | `instr = 03` | |
| **② 译码** | `is_add = 1` | `rd=0`、`rs1=0`、`rs2=0` |
| **③ 读操作数** | `MUX_raddr1` 的 `S=00` → `rs1=0` | **`rdata1 = R[0] = 12`** |
| **④ 读操作数 2** | `raddr2 = rs2 = 0` | **`rdata2 = R[0] = 12`** |
| **⑤ ALU** | `12 + 12` | **`result = 24`** |
| **⑥ 选写回数据** | `S = 01`（`S0=is_add=1`）| **D1 = alu.result = 24** |
| **⑦ 写 GPR** | `wen = 1` | **`R[0] = 24`** |
| **⑧ 更新 PC** | `pc_taken = 0` | **PC = 2** |

### `bner0 r3, -3`（机器码 `F7`）

```
F7 = 1111 0111
     ↑↑↑↑ ↑↑↑↑
     |||| |└┴── rs2    = 11（r3）
     |||| └───── offset = 1101（-3，4 位补码）
     └───┴───── opcode = 11（bner0）
```

| 步骤 | 信号 | 值 |
| :-: | --- | --- |
| **① 取指** | `instr = F7` | |
| **② 译码** | `is_bner0 = 1` | `offset=1101`、`rs2=3` |
| **③ 读 R[0]** | **`MUX_raddr1` 的 `S=01` → 选 0** | **`rdata1 = R[0] = 24`** ⭐ |
| **④ 读 R[rs2]** | `raddr2 = 3` | **`rdata2 = R[3]`** |
| **⑤ 比较** | `cmp.A = 24`，`cmp.B = R[3]` | **不等 → `bne = 1`** |
| **⑥ 跳转判断** | `pc_taken = is_bner0 · bne` | **= 1** |
| **⑦ 算 offset8** | `Bit Extender`（**Sign Extend**）| **`11011101`？不 —— `-3` → `11111101`** |
| **⑧ 加法器 B 端** | `MUX_addB` 的 `S=1` → 选 `offset8` | **`11111101`（-3）** |
| **⑨ 算新 PC** | `PC + (-3)` | **PC 后退 3** ✅ |
| **⑩ 不写 GPR** | `wen = 0` | |

| 指令 | `wdata` | `wen` | `raddr1` | 加法器 B 端 |
| :-: | --- | :-: | --- | --- |

| # | 选择点 | 选择端 | 作用 |
| :-: | --- | --- | --- |

| 3 | **`MUX_addB`** | `pc_taken` | **PC 加 1 还是加 offset** |

## 十、答辩常见问题

### Q1：F6 相对 F5 最大的改进是什么？

> **两个**：
> 1. **`li` 加强** —— **装大常数从 7 条指令 → 1 条**（程序短一半以上）
> 2. **加了 `io`** —— **从"跑完看寄存器"变成"能跟外设交互"** —— **这才是真实处理器**

### Q2：`li` 的 `s` 字段为什么能装大数？

> **`s` 是"移位选择"** —— **`imm`（2 位）放在 8 位的哪一段**：
> `s=00` 放最低 2 位、`s=11` 放最高 2 位。
>
> **相当于"1 条指令里编码了 4 种移位量"** ——
> **用 2 位换来了"能装 0~192"的能力** ✅

### Q3：`bner0` 为什么要"符号扩展"？

> **因为 `offset` 可以是负数**（往回跳）。
>
> 4 位补码 `1111` = **-1**：
> - **零扩展** → `00001111` = **+15**（错）
> - **符号扩展** → `11111111` = **-1**（对）
>
> **—— 数据"有符号"时，必须用符号扩展** ⚠️

### Q4：为什么 `bner0` 要改成"相对偏移"？

> **三个好处**：
> 1. **跳转范围变大**（-8~+7，比 0~15 的绝对地址灵活）
> 2. **代码可以整体搬移**（位置无关）
> 3. **复用 PC 加法器**（省硬件）
>
> **这是现代处理器的标准做法**（RISC-V 的 `beq` 也是相对偏移）✅

### Q5：`io` 为什么用一条指令做"读"和"写"？

> **因为 `i/o` 位切换方向、`idx` 选设备** ——
> **一个操作码槽位就够**，**不需要两条指令**。
>
> **—— 用最少的位数表达最多的功能**，这是 ISA 设计的核心目标 ✅

### Q6：为什么 `io` 要读 `R[rd]`，而 `add` 读 `R[rs1]`？

> **因为 `io` 的语义是「`R[rd]` 和 `dev[idx]` 交换数据」** ——
> **读写都是 `R[rd]`**（不像 `add` 是"读 rs1/rs2、写 rd"）。
>
> **所以 `MUX_raddr1` 必须按指令切换到 `rd`** ⚠️
> **—— 这是 F6 最隐蔽的坑**

### Q7：输出设备为什么要"锁存"？

> **因为 `io` 指令只持续 1 拍** ——
> **不锁存的话，LED 只亮一个时钟周期**（肉眼看不见）。
>
> **用 Register 锁存后，输出保持到下次写** ✅

### Q8：为什么 `io` 输出时 `wen = 0`？

> **`io` 输出只是"把 `R[rd]` 送到设备"，不需要写回 `R[rd]`**。
>
> **如果 `wen = 1`** → **会把 `io_rdata`（设备输入值）写进 `R[rd]`** → **数据被破坏** ❌
>
> **—— 所以 `wen` 要用 `is_io AND NOT io_dir`（`S1`）** ⚠️

### Q9：你的电路和讲义建议的不一样（用了 Shifter 而不是 MUX）？

> **讲义说"可以将 `s` 看成选择信号，用多路选择器实现"** ——
> **我用 `Shifter`，本质一样**（都是"按 `s` 选择移位量"），
> **但 `Shifter` 只需 1 个元件 + 1 个 `s*2` 拼接**，
> **比 4 选 1 MUX + 4 个移位常量更简单**。
>
> **—— 理解了原理后，实现方式可以自由选择** ✅

### Q10：如果让你继续改进 sCPU，你会做什么？

> **三个方向**：
> 1. **加更多设备**（`idx` 有 3 位，能用 8 个）
> 2. **加"中断"**（不用轮询，设备主动通知 CPU）
> 3. **加"流水线"**（讲义"迈向现代化"那节的方向）
>
> **—— 这就是从"简易 CPU"到"真实 CPU"的路** ✅

### Q11：`io` 的 `idx` 只有 3 位，够用吗？

> **够** —— **两个方向各能连 8 个设备**（共 16 个）。
>
> **而且编号可以复用**（LED 和拨码共用 `000`）—— **实际能连更多** ✅
>
> **如果不够**，可以**扩大 `idx` 字段**（但指令还是 8 位，要从别处省位）。

### Q12：这个 CPU 能跑"真正的程序"吗？

> **能跑"用 sISA 写的程序"** —— 比如：
> - **读拨码 → 显示**
> - **计数器（循环 + 显示）**
> - **简单计算器**
>
> **但 sISA 只有 4 条指令、8 位数据** ——
> **要跑"真正的程序"（比如游戏），需要 v24.07 的 F6（minirv / RISC-V）** ✅
>
> **—— 这就是我下一步要做的加分项**（可以主动说，显得有规划）

## 十一、我踩过的坑

### 坑 1：`io` 读到的是 `R[rs1]` 而不是 `R[rd]`

**现象**：`in r0, 拨码` 后 `r0` 是错的。

**原因**：**`io` 的 `rd` 在 bit 5~4**，**但 `MUX_raddr1` 只接 `rs1`（bit 3~2）**。

**修正**：`MUX_raddr1` 从 2 选 1 改成 3 选 1，加一路 `dec.rd`。

**教训**：

> **同一个位段，不同指令可以有不同含义** ——
> **译码时要按"当前指令"解释，不能固定成一个字段** ⚠️

### 坑 2：`bner0` 的 offset 算错

**现象**：程序不循环 / 跳到中间。

**原因**：**`bner0` 是"相对偏移"**，不是"绝对地址"。

**修正**：**要跳回地址 0，当前 PC=3 → `offset = 0 - 3 = -3`**（不是 `0`）。

**教训**：

> **`bner0` 的 offset = 目标 − 当前** —— **算的时候要用减法** ⚠️

### 坑 3：`MUX_wdata.D2` 接成了常量 0

**现象**：`in` 读进来的值一直是 0。

**原因**：**改动 1 时 `D2` 用常量 0 占位**，**改动 5 忘了改接 `io_rdata`**。

**修正**：`MUX_wdata.D2 ← io_rdata`。

**教训**：

> **占位用的常量，改动完成后一定要"回头替换"** ——
> **最好在占位上打 `Label`（比如 `TODO_D2`）**，一眼能看到还没接 ⚠️

### 坑 4：`r0` 拍完变成 255

**现象**：改 `MUX_wdata` 之后，`r0` 变成 255。

**原因**：**`MUX_wdata.D0` 接成了 `offset8`**（不是 `imm8`）。

**为什么是 255**：`offset = 1111` → 符号扩展 → `11111111` = **255**。

**修正**：

```
D0 ← Shifter.Output（imm8）
offset8 只能接 MUX_addB.D1
```

**教训**：

> **两个 Bit Extender（`imm` 的零扩展 / `offset` 的符号扩展）输出去向完全不同** ——
> **别接串了** ⚠️

> **我在 F5 的基础上完成了 F6：sISA 从 3 条指令扩展到 4 条。**
>
