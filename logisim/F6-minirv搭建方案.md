## 一、minirv 规范

**讲义原文**：

> - The initial value of PC is `0`.
> - The number of GPRs is the same as that defined in **RV32E**.
> - It supports the following 8 instructions: `add`, `addi`, `lui`, `lw`, `lbu`, `sw`, `sb`, `jalr`
> - Other ISA details are the same as those of RV32I.

| 项目 | 值 | 和 sCPU 的对比 |
| --- | --- | --- |
| **PC** | **32 位**，初值 0 | sCPU 是 8 位 |
| **GPR** | **16 个 × 32 位**（RV32E）| sCPU 是 4 个 × 8 位 |
| **指令** | **32 位** | sCPU 是 8 位 |
| **存储器编址** | **按字节**（8 位）| sCPU 只有取指 |
| **`R[0]`** | **恒为 0** ⭐ | sCPU 是普通寄存器 |
| **立即数** | **符号扩展**（I/S 型）| sCPU 是零扩展 |

### 8 条指令一览

| 指令 | 功能 | 格式 |
| --- | --- | :-: |
| **`add rd, rs1, rs2`** | `R[rd] = R[rs1] + R[rs2]` | **R** |
| **`addi rd, rs1, imm`** | `R[rd] = R[rs1] + sext(imm)` | **I** |
| **`lui rd, imm`** | `R[rd] = imm << 12` | **U** |
| **`lw rd, offset(rs1)`** | `R[rd] = M[R[rs1] + sext(offset)]` | **I** |
| **`lbu rd, offset(rs1)`** | `R[rd] = zext(M8[...])` | **I** |
| **`sw rs2, offset(rs1)`** | `M[...] = R[rs2]` | **S** |
| **`sb rs2, offset(rs1)`** | `M8[...] = R[rs2][7:0]` | **S** |
| **`jalr rd, offset(rs1)`** | `R[rd] = PC+4; PC = R[rs1] + sext(offset)` | **I** |

### 指令编码（RV32I）

**R 型**（`add`）：

```
 31      25 24    20 19    15 14  12 11     7 6       0
+----------+--------+--------+------+--------+---------+
|  funct7  |  rs2   |  rs1   |funct3|   rd   | opcode  |
+----------+--------+--------+------+--------+---------+
```

**I 型**（`addi`、`lw`、`lbu`、`jalr`）：

```
 31              20 19    15 14  12 11     7 6       0
+------------------+--------+------+--------+---------+
|    imm[11:0]     |  rs1   |funct3|   rd   | opcode  |
+------------------+--------+------+--------+---------+
```

**S 型**（`sw`、`sb`）：

```
 31      25 24    20 19    15 14  12 11     7 6       0
+----------+--------+--------+------+--------+---------+
| imm[11:5]|  rs2   |  rs1   |funct3|imm[4:0]| opcode  |
+----------+--------+--------+------+--------+---------+
```

**U 型**（`lui`）：

```
 31                      12 11     7 6       0
+--------------------------+--------+---------+
|        imm[31:12]        |   rd   | opcode  |
+--------------------------+--------+---------+
```

**8 条指令的编码表**（**必须背下来**）：

| 指令 | `opcode`<br>(bit 6~0) | `funct3`<br>(bit 14~12) | `funct7`<br>(bit 31~25) |
| --- | :-: | :-: | :-: |
| **`add`** | **`0110011`** | `000` | `0000000` |
| **`addi`** | **`0010011`** | `000` | — |
| **`lui`** | **`0110111`** | — | — |
| **`lw`** | **`0000011`** | `010` | — |
| **`lbu`** | **`0000011`** | `100` | — |
| **`sw`** | **`0100011`** | `010` | — |
| **`sb`** | **`0100011`** | `000` | — |
| **`jalr`** | **`1100111`** | `000` | — |

**⚠️ 注意 `opcode` 最低两位恒为 `11`**（RISC-V 约定，非压缩指令）。

## 二、⚠️ 陷阱 1：PC 和 ROM 的宽度

**这是最容易被忽略的坑** —— **讲义专门用一节讲**。

### 问题

**RISC-V 规定**：

> **存储器的宽度是「字节（8 位）」** —— **PC 按字节编址**。

**但指令是 32 位（4 字节）** —— **所以**：

```
PC = 0   → 第 0 条指令（字节 0~3）
PC = 4   → 第 1 条指令（字节 4~7）
PC = 8   → 第 2 条指令（字节 8~11）
```

**⚠️ 如果 ROM 做成「256 × 32」**（每条指令 32 位）：
- **ROM 的地址是"指令编号"（0、1、2…）**
- **但 PC 是"字节地址"（0、4、8…）**
- **→ 不能直接把 PC 接 ROM 的地址** ❌

### 解法：**PC 的低 2 位丢掉**

```
ROM 地址 = PC[31:2]     （PC 除以 4）
```

**Logisim 实现**：**用一个 Splitter**

```
Splitter（拆 PC）
  Input Bit Width = 32
  Fan Out = 2
  Bit 0~1 = 0      （低 2 位，丢弃不用）
  Bit 2~31 = 1     （高 30 位 → ROM 地址）
```

**或者**：**如果 ROM 只有 256 条，取 `PC[9:2]`**（8 位地址）：

```
Splitter
  Bit 0~1 = 0      （丢弃）
  Bit 2~9 = 1      （8 位 → ROM 地址）
  Bit 10~31 = 2    （丢弃）
```

**⚠️ 但 PC 是 32 位的"字节地址"** —— **所以 `PC + 4` 才是"下一条"**（不是 +1！）

**—— 这是 sCPU → minirv 最大的思维切换** ⚠️

### 对照表

| | sCPU | **minirv** |
| --- | :-: | :-: |
| **PC 增量** | **+1** | **+4** ⭐ |
| **PC 位宽** | 8 | **32** |
| **指令宽度** | 8 | **32** |
| **ROM 地址** | **直接接 PC** | **PC[9:2]**（除以 4）|

## 三、⚠️ 陷阱 2：`R[0]` 恒为 0

**讲义的问题 3**：

> 「What are the differences between `R[0]` and `R[0]` in sISA?」

**答案**：

| | sCPU 的 `R[0]` | **RISC-V 的 `x0`** |
| --- | --- | --- |
| **作用** | **普通寄存器**（`bner0` 拿它当循环上界）| **恒为 0**（写入无效）⭐ |
| **写入** | 可以 | **无效**（永远读 0）|

**—— 为什么 RISC-V 要这么做**：

> **`x0` 恒为 0，可以当"零寄存器"用** ——
> **`addi x0, x0, 5`** = **"什么都不做"**（NOP）
> **`add x1, x0, x2`** = **"把 x2 复制到 x1"**（MOV）
> **—— 省掉了一条 MOV 指令** ✅

**Logisim 实现**：

```
gpr.wen 的 5 位地址 == 0 时 → 不写
```

**即**：**`wen_actual = wen AND (waddr != 0)`**

**—— 可以用一个 5 输入 NOR 门检测 `waddr == 0`** ✅

## 四、⚠️ 陷阱 3：译码要用比较器

**讲义原话**：

> 「Although there are decoders in the Logisim component library, since there are not many instructions in minirv, **the opcode encoding is relatively sparse**, and using a decoder will bring some inconvenience instead.
> Therefore, we recommend that you use a **comparator**。」

**为什么不用译码器**：

| 方案 | 问题 |
| --- | --- |
| **7-128 译码器** | **opcode 有 7 位 → 128 个输出**，但**只用 8 个** —— 浪费 |
| **比较器** ✅ | **每条指令一个比较器**（`opcode == 0110011`）—— **干净** |

**8 条指令的检测**：

```
is_add   = (opcode == 7'b0110011)
is_addi  = (opcode == 7'b0010011)
is_lui   = (opcode == 7'b0110111)
is_lw    = (opcode == 7'b0000011) && (funct3 == 3'b010)
is_lbu   = (opcode == 7'b0000011) && (funct3 == 3'b100)
is_sw    = (opcode == 7'b0100011) && (funct3 == 3'b010)
is_sb    = (opcode == 7'b0100011) && (funct3 == 3'b000)
is_jalr  = (opcode == 7'b1100111) && (funct3 == 3'b000)
```

**⚠️ 注意 `lw`/`lbu` 共用 opcode**（`0000011`）—— **靠 `funct3` 区分** ✅
**`sw`/`sb` 也共用**（`0100011`）—— **靠 `funct3` 区分** ✅

## 八、模块 3：`dec`

### 接口

**输入**：`instr`（32 位）

**输出**（**14 个**）：

| 输出 | 位宽 | 说明 |
| --- | :-: | --- |
| `is_add` | 1 | |
| `is_addi` | 1 | |
| `is_lui` | 1 | |
| `is_lw` | 1 | |
| `is_lbu` | 1 | |
| `is_sw` | 1 | |
| `is_sb` | 1 | |
| `is_jalr` | 1 | |
| **`rd`** | **5** | 目的寄存器（bit 11~7）|
| **`rs1`** | **5** | 源寄存器 1（bit 19~15）|
| **`rs2`** | **5** | 源寄存器 2（bit 24~20）|
| **`imm_i`** | **32** | I 型立即数（符号扩展）|
| **`imm_s`** | **32** | S 型立即数（符号扩展）|
| **`imm_u`** | **32** | U 型立即数（`imm << 12`）|

### 内部：4 个 Splitter + 8 个比较器

**Splitter #1（拆主要字段）**：

| 属性 | 值 |
| --- | :-: |
| `Input Bit Width` | **32** |
| `Fan Out` | **7** |
| `Bit 0~6` | **0** → `opcode`（7 位）|
| `Bit 7~11` | **1** → `rd`（5 位）|
| `Bit 12~14` | **2** → `funct3`（3 位）|
| `Bit 15~19` | **3** → `rs1`（5 位）|
| `Bit 20~24` | **4** → `rs2`（5 位）|
| `Bit 25~31` | **5** → `funct7`（7 位）|
| （不用）| 6 |

**Splitter #2（拆 I 型立即数）**：

**I 型**：`imm[11:0]` = **bit 31~20**

```
Bit 20~31 = 0     （12 位 imm_i 原始值）
Bit 0~19  = 1     （不用）
```

**然后**：**Bit Extender（Sign Extend，12→32）**

**Splitter #3（拆 S 型立即数）**：

**S 型**：`imm[11:5]` = **bit 31~25**、`imm[4:0]` = **bit 11~7**

**⚠️ 这是"分散"的** —— **要拼接**：

```
Splitter（合并，Facing=West）
  Input Bit Width = 12
  Bit 0~4  = 0     （来自 bit 11~7）
  Bit 5~11 = 1     （来自 bit 31~25）
```

**然后**：**Bit Extender（Sign Extend，12→32）**

**Splitter #4（拆 U 型立即数）**：

**U 型**：`imm[31:12]` = **bit 31~12**

```
Bit 12~31 = 0     （20 位）
Bit 0~11  = 1     （不用）
```

**然后**：**左移 12 位**（或者直接当"高位"用）

**—— `imm_u` 的 32 位值 = `{instr[31:12], 12'b0}`** ✅

### 8 个比较器

**每个比较器**：`opcode`（7 位）== 常量

```
Comparator（Numeric Width = 7）
  A ← opcode
  B ← 常量（比如 7'b0110011）
  = 输出 → is_add
```

**⚠️ `lw`/`lbu`/`sw`/`sb` 还要检查 `funct3`**：

```
is_lw = (opcode == 7'b0000011) AND (funct3 == 3'b010)
```

**—— 需要额外的比较器 + AND 门** ✅

## 九、模块 4：`gpr`

### 接口

| 端口 | 方向 | 位宽 |
| --- | :-: | :-: |
| **`raddr1`** | 输入 | **5** |
| **`rdata1`** | 输出 | **32** |
| **`raddr2`** | 输入 | **5** |
| **`rdata2`** | 输出 | **32** |
| **`waddr`** | 输入 | **5** |
| **`wdata`** | 输入 | **32** |
| **`wen`** | 输入 | 1 |
| **`clk`** | 输入 | 1 |

### 实现（**16 个 32 位寄存器**）

```
16 个 Register（Data Bits = 32）
+ 2 个 Multiplexer（Select Bits = 4, Data Bits = 32）
+ 1 个 Decoder（4-16）
+ 16 个 AND 门
```

**⚠️ `raddr1` 是 5 位，但只有 16 个寄存器** —— **只用低 4 位**：

```
raddr1[3:0] → MUX 的 S（4 位）
```

**（`raddr1[4]` 不用，或者接 0）**

### ⭐ `R[0]` 恒为 0 的实现

**两种做法**：

| 做法 | 说明 |
| --- | --- |
| **A. 不写 R0** | **`wen_actual = wen AND (waddr != 0)`** ✅ |
| **B. 读 R0 时返回 0** | **`rdata1 = (raddr1 == 0) ? 0 : gpr[raddr1]`** |

**✅ 推荐 A（更简单）**：

```
写使能译码：
  waddr[3:0] → 4-16 译码器 → Y0~Y15
  Y_i · wen · (waddr != 0) → AND → Reg_i 的 WE
```

**`waddr != 0` 的检测**：**5 输入 NOR 门**（全 0 时输出 1）

```
NOT(waddr==0) —— 或者反过来用
```

**（注意：0 是 5 位全 0）**

## 十一、模块 6：`dmem`（数据存储器）

**这是全新模块**（sCPU 没有）。

### 接口

| 端口 | 方向 | 位宽 |
| --- | :-: | ---: |
| **`addr`** | 输入 | **32** |
| **`wdata`** | 输入 | **32** |
| **`we`** | 输入 | 1（写使能）|
| **`clk`** | 输入 | 1 |
| **`rdata`** | 输出 | **32** |

### 两种实现

| 方案 | 说明 | 难度 |
| --- | --- | :-: |
| **A. 用 Logisim 的 `RAM`** | **属性：`Address Bit Width`、`Data Bit Width`** | ⭐ |
| **B. 用 16 个 32 位寄存器 + MUX** | **自己搭** | ⭐⭐⭐ |

**✅ 推荐 A** —— **Logisim 有现成的 `RAM`**：

```
Memory → RAM
  Address Bit Width = 8     （256 字节）
  Data Bit Width    = 32
```

**⚠️ 地址要"除以 4"**（和 ROM 一样）：

```
addr[9:2] → RAM 的地址
```

**⚠️ `lbu`（加载字节）要特殊处理**：

```
lbu：读 32 位，但只取低 8 位？
```

**—— 嗯，如果 RAM 是"按字（32 位）编址"**，**那 `lbu` 需要"字内偏移"**：

```
字节地址 = R[rs1] + imm
字地址   = 字节地址[31:2]
字内偏移 = 字节地址[1:0]
```

**然后**：**从 32 位字里选 1 个字节**（4 选 1 MUX）→ **零扩展成 32 位**

**—— 这是 `lbu`/`sb` 的复杂性所在** ⚠️

**⚠️ 简化方案**：**如果只要求"按字访问"**（不做字节粒度）：

- **`lbu` 简化成"取低 8 位并零扩展"**
- **`sb` 简化成"写低 8 位，高 24 位不变"**

**—— 但这不是"完整的 RISC-V 行为"** ⚠️

**✅ 建议**：**先做"按字访问"版本**（能跑大部分程序），**再考虑字节粒度**。

## 十二、模块 7：跳转与地址生成

### PC 的 4 种来源

| 情况 | PC 新值 |
| --- | --- |
| **正常执行** | **PC + 4** |
| **`jalr`** | **R[rs1] + sext(imm)** |
| **复位** | 0 |

**—— 其实只有 2 种**（`PC+4` 或 `jalr`）✅

### 实现

```
MUX_pc（2 选 1，32 位）
  D0 ← PC + 4
  D1 ← jalr_target
  S  ← is_jalr
  Y  → pc_next
```

**`jalr_target` = `R[rs1] + sext(imm_i)`** —— **复用 ALU** ✅

**⚠️ 注意 RISC-V 的 `jalr` 要把最低位清零**：

```
PC = (R[rs1] + sext(imm)) & ~1
```

**—— 因为 RISC-V 要求"指令地址 2 字节对齐"**（非压缩指令实际是 4 字节对齐）

**嗯，标准 RV32I 的 `jalr` 是 `PC = (rs1 + imm) & ~1`** —— **`~1` 清 bit 0**。

### 写回数据 MUX（4 选 1）

| `S` | 来源 | 指令 |
| :-: | --- | --- |
| `00` | **`alu.result`** | `add`、`addi` |
| `01` | **`dec.imm_u`** | **`lui`** |
| `10` | **`dmem.rdata`** | **`lw`、`lbu`** |
| `11` | **`PC + 4`** | **`jalr`**（返回地址）⭐ |

### 写使能

```
gpr.wen = (is_add | is_addi | is_lui | is_lw | is_lbu | is_jalr)
          AND (rd != 0)                    ← R[0] 恒为 0
```

**⚠️ `sw`/`sb` 不写 GPR**（写存储器）✅

```
dmem.we = (is_sw | is_sb)
```

## 十六、常见陷阱清单

| # | 陷阱 | 说明 |
| :-: | --- | --- |
| **1** | **PC 是字节地址** | **`PC + 4`**，不是 `PC + 1` ⚠️ |
| **2** | **ROM 地址要 `PC[9:2]`** | **除以 4** ⚠️ |
| **3** | **`R[0]` 恒为 0** | **`wen AND (waddr != 0)`** ⚠️ |
| **4** | **`lw`/`lbu` 共用 opcode** | **靠 `funct3` 区分** |
| **5** | **`sw`/`sb` 共用 opcode** | **靠 `funct3` 区分** |
| **6** | **I 型立即数符号扩展** | **12 → 32 位 Sign Extend** |
| **7** | **S 型立即数是"分散"的** | `imm[11:5]` 在 bit 31~25、`imm[4:0]` 在 bit 11~7 → **要拼接** ⚠️ |
| **8** | **U 型立即数是"高位"** | `imm << 12`（低 12 位补 0）|
| **9** | **`jalr` 的返回值** | **`R[rd] = PC + 4`**（不是 PC）⭐ |
| **10** | **`jalr` 的 `PC` 要清 bit 0** | `PC = (rs1+imm) & ~1` |
| **11** | **32 位加法的进位** | **Logisim 的 Adder 自动处理**（Data Bits = 32）|
| **12** | **16 个寄存器 vs 5 位地址** | **只用低 4 位**（`raddr[3:0]`）|
